# 模块定位与职责边界

## 模块解决什么问题

长期记忆模块负责管理跨 Thread、跨任务持续存在的用户信息，并在当前任务需要时，从长期记忆、用户 Profile、业务数据库和领域知识库中检索相关证据。

它解决的并不是「如何把历史聊天重新放进 Prompt」，而是两个更底层的问题：哪些信息值得长期保存，以及当前任务真正需要哪些长期事实和外部知识。

系统中的 LangGraph Checkpointer（保存型记忆中图执行位置的持久化机制，见第一章 [[项目梳理/个人健康管理agent/1.Harness 控制平面与任务状态编排/5.Task Runtime、Checkpoint 和业务状态#LangGraph 检查点语义]]）只负责 Thread 范围内的运行状态与对话恢复，例如当前 Graph 执行到哪个节点、任务中断后从哪里恢复。这类状态属于 Harness 控制状态（Control State），不等同于长期 Memory。长期记忆以 `user_id` 为主要作用域，即使用户开启新的 Conversation Thread，仍然能够读取已经形成的长期认知。

## 与上下文装配的接口

第三章不负责最终 Prompt 拼装。Memory、Profile、Business DB 和 Domain Knowledge 经过检索与证据处理后统一输出 `EvidenceBundle`，由第二章的 Context Assembler（上下文装配器，见 [[项目梳理/个人健康管理agent/2.上下文工程与能力渐进装载/3.上下文装配器与 ContextPolicy]]）决定哪些 Evidence 进入当前 LLM Context、采用什么顺序以及占用多少 Token。

两个模块之间的分工：

```text
第三章：
长期信息如何保存
→ 当前任务需要检索什么
→ 哪些事实当前有效
→ 证据来自哪里
→ 输出 EvidenceBundle
    │
    └── 交给第二章
第二章：
EvidenceBundle 中哪些内容进入本轮 Context
→ 如何裁剪
→ 如何组织
→ 如何与 Task Status、Conversation Context 一起装配
```

## 与多智能体的权限边界

第五章的 Conversation Supervisor（会话主管）和 Domain Agent（领域智能体）也不会默认共享所有用户 Memory。Supervisor 或 Domain Agent 根据当前 `DomainTask` 判断是否需要长期用户信息或领域知识，再显式调用对应 Retrieval Capability。

普通常识问题不触发 Memory Retrieval，需要领域个性化信息时才读取相关 Evidence，从而避免长期 Memory 重新演化成一份所有 Agent 每轮都加载的全局上下文。Supervisor 的委派协议见 [[项目梳理/个人健康管理agent/5.多智能体协作与异步任务执行/4.Supervisor 架构与委派]]，Domain Agent 的执行模型见 [[项目梳理/个人健康管理agent/5.多智能体协作与异步任务执行/5.Domain Agent 执行模型]]。

## 四类数据来源

整个长期信息体系的数据来源最终分为四类：

```text
User Profile
→ 当前高价值用户状态

User Memory
→ 跨会话保存的用户历史与长期认知

Business DB
→ 正式业务事实

Domain Knowledge
→ 健身 / 饮食领域公共知识
```

这些数据可以共同支持一次 Agent Task，但不会因为统一进入 Evidence Assembly 就混成同一种存储。每一类的读写语义和存放位置各不相同，见 [[4.长期记忆语义模型]] 与 [[8.证据检索#业务事实归业务库]]。

## 边界问答

**1. Q：** 长期记忆和 LangGraph Checkpointer 有什么区别？

**A：** Checkpointer 只负责 Thread 范围内的运行状态与对话恢复，属于 Harness 控制状态；长期记忆以 `user_id` 为主要作用域，面向跨会话、跨任务的用户信息。前者回答「这个任务执行到哪、中断后从哪恢复」，后者回答「关于这个用户，系统应长期保存什么、当前任务需要什么」。

**2. Q：** 为什么第三章不直接拼装 Prompt？

**A：** 第三章只负责把四类数据统一转成 `EvidenceBundle` 并保留来源、标记有效性、识别冲突；哪些内容进入本轮模型上下文、顺序与 Token 预算，由第二章 Context Assembler 决定。

**3. Q：** 为什么不把所有 Memory 默认共享给每个 Agent？

**A：** Supervisor 或 Domain Agent 根据当前 `DomainTask` 显式判断是否需要长期用户信息，再调用对应 Retrieval。普通常识问题不触发 Memory Retrieval，这样避免长期 Memory 变成每个 Agent 每轮都加载的全局上下文，也避免无关信息污染模型上下文。
