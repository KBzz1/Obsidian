# 能力渐进装载

## 问题：全量注册的注意力分散

随着系统集成的能力变多，把所有业务领域的技能指令（Skill Prompt）和工具描述全量注册进单一上下文，会让模型注意力分散。能力渐进装载就是把技能指令和工具描述按执行深度分层挂载：浅层节点只看到轻量描述，执行指针深入具体技能时，才挂入完整指令和专属工具。

## 作用域逐级收敛

能力作用域由上至下逐级收敛：

```text
Supervisor
    ↓
轻量业务领域能力描述
    ↓
训练 / 饮食 / 习惯等业务领域
    ↓
领域智能体
    ↓
只加载本领域技能与工具
    ↓
必要时选择具体技能
    ↓
技能执行器
    ↓
完整技能指令 + 对应工具
```

Supervisor 是请求进入系统时选择执行目标的路由决策者（见 [[4.Supervisor 架构与委派]]）；技能执行器是具体技能的工作流，承担该技能的实际执行。只有任务的执行指针真正切入某项特定技能时，该技能的高级指令参数和专属工具链才会被挂入。

## 示例：能力按业务域和技能渐进装载

以「修改训练计划」任务为例。系统能力注册表先按业务域登记：

```json
{
  "domains": [
    {
      "name": "workout",
      "description": "训练计划、训练记录、动作调整"
    },
    {
      "name": "diet",
      "description": "饮食记录、营养分析、饮食计划"
    },
    {
      "name": "habit",
      "description": "习惯创建、打卡和提醒"
    }
  ]
}
```

Supervisor 只读取业务域。进入 Workout Agent 后，才读取训练领域的技能：

```json
{
  "skills": [
    {
      "name": "create_workout_plan",
      "description": "创建训练计划"
    },
    {
      "name": "revise_workout_plan",
      "description": "修改已有训练计划"
    },
    {
      "name": "query_training_history",
      "description": "查询训练历史"
    }
  ]
}
```

确定当前任务属于 `revise_workout_plan` 后，才加载具体工具：

```json
{
  "skill": "revise_workout_plan",
  "allowed_tools": [
    "search_exercise",
    "evaluate_training_load",
    "update_plan_draft"
  ],
  "forbidden_tools": [
    "publish_plan",
    "delete_plan"
  ]
}
```

能力加载链路：

```text
所有系统能力
  ↓
Supervisor 只加载业务域
  ↓
Workout Agent 加载训练技能
  ↓
Skill Loader 加载计划修改技能
  ↓
上下文装配器加载对应工具模式
  ↓
模型获得当前节点允许的能力
```

渐进装载的重点不是「工具越少越好」，而是让模型在当前节点只看到与当前任务相关、且当前阶段允许使用的能力。

## 确定性路由，不是运行时改工具

渐进装载不是对单一智能体的工具列表做高频随机篡改，而是由装配器在预定义的上下文策略配置里做确定性路由选择（见 [[3.上下文装配器与 ContextPolicy]]）。

## 隔离效果

训练领域智能体在其生命周期内对饮食领域的工具定义处于隔离状态，饮食节点同样触达不到训练计算工具。单次上下文规模缩小的同时，业务领域之间的边界被强化，模型不再需要在海量无关能力里做甄别选择。

## 边界问答

**1. Q：** 为什么不把所有工具一次性注册进上下文？

**A：** 全量注册会带来注意力分散，模型需要在海量无关能力里做甄别选择，单次上下文规模也更大。按执行深度分层装载，只有切入具体技能时才挂入完整指令和专属工具。

**2. Q：** 为什么强调确定性路由而不是运行时动态增删工具？

**A：** 渐进装载的载体是装配器在预定义上下文策略配置中的确定性路由选择，而不是运行时对单一智能体工具列表的高频随机篡改；工具的可见范围由策略配置决定。

**3. Q：** 渐进装载是不是工具越少越好？

**A：** 不是。重点是让模型在当前节点只看到与当前任务相关、且当前阶段允许使用的能力；该阶段不需要的能力即使数量不多也不该出现，需要的完整指令和工具链也不能因为追求精简而缺失。
