# OpenAI 兼容生态：事实标准的形成

## 事实标准是怎么形成的

OpenAI 没有把 Chat Completions 提交给任何标准组织，但它成了事实标准（de facto standard）：2023 年它随 GPT-3.5/GPT-4 时代铺开，SDK、教程、开源项目大量以它的字段结构写死；后续出现的模型服务商与推理引擎面对的问题不是「设计什么 API」，而是「怎么让存量代码零改动迁移」。答案高度一致：实现一个长得和 `/v1/chat/completions` 一样的端点。于是「OpenAI-compatible endpoint」成了行业通用词，指接受 messages 请求体、返回 chat.completion 形态响应的服务。

## 兼容的三层含义

一个服务宣称「OpenAI 兼容」，通常指三层全部或部分成立：

**协议层**：同样的路径（`/v1/chat/completions`，部分服务再加自己的前缀）、同样的 Bearer 鉴权、messages / choices / finish_reason / usage 字段名一致。

**SDK 层**：官方 OpenAI SDK 只换 `base_url` 与 `api_key` 就能直接调用——SDK 把差异收敛在初始化参数里，业务代码一行不改。

```python
from openai import OpenAI
client = OpenAI(
    base_url="https://api.deepseek.com",   # 换成兼容服务的地址
    api_key="sk-...",                       # 该服务签发的 key
)
resp = client.chat.completions.create(      # 以下与调 OpenAI 完全相同
    model="deepseek-chat",
    messages=[{"role": "user", "content": "你好"}],
)
```

**行为层**：工具调用往返、流式 chunk、finish_reason 语义按 OpenAI 的行为工作。这一层最难做也最常出差异。

按这个口径，2026-09 的兼容版图大致三类：模型厂商直接提供兼容端点（DeepSeek、月之暗面、智谱、MiniMax、阿里的兼容模式等）；开源推理引擎天然只输出兼容端点（vLLM、SGLang、Ollama、llama.cpp 的 server 模式）；聚合路由平台把上百个模型统一在一个兼容端点后（OpenRouter、SiliconFlow、Groq 等）。

## 兼容的边界

兼容承诺的是 Chat Completions 的基本盘，边界在四处：

**新特性滞后或缺失**。`strict` 约束解码、logprobs、高级采样参数、多模态输入这些能力取决于各家实现，兼容端点不保证支持——参数发过去可能被忽略、报错甚至静默改变行为。依赖新特性前要逐项验证，不能因为「格式一样」就认为能力一样。

**行为差异真实存在**。工具调用的稳定性、流式切片的粒度、finish_reason 的出现时机，各家模型能力不同，同一份提示词在不同兼容端点上的效果不等价。base_url 换得掉接口，换不掉模型。

**版本演进不同步**。OpenAI 自身在往 Responses 走（见 [[3.1 Items 模型：input、output 与 instructions]]），Chat Completions 处于维护状态；兼容生态锁在 Chat Completions 形态上，OpenAI 的新一代格式并没有被兼容层普遍跟进。事实标准也有自己的生命周期。

**错误码与限流语义各家自定义**。429 限流、5xx 重试、模型名不存在时的报错格式没有统一约定，多供应商路由层要按各家文档分别处理（HTTP 状态码五族的基础语义与重试分界见 [[3.HTTP：请求响应、方法、头部与状态码]]）。

## 边界问答

**1. Q：** 「OpenAI 兼容」和「OpenAI 官方」怎么区分，写代码时要区分吗？
**A：** 官方端点是 api.openai.com，官方模型是 gpt 系；兼容端点是各家用自己的域名与模型名、复用格式。代码层面通过 base_url 与 model 参数切换，不必区分；排障层面必须区分——行为差异与能力缺失只出现在兼容端点上，issue 要提给对应服务商。

**2. Q：** 面试怎么说「为什么大家都兼容 OpenAI 格式」？
**A：** 三个词：存量代码、切换成本、生态复用。迁移成本决定采用意愿——兼容格式让新服务第一天就能接入所有已写好的 OpenAI SDK 代码；反过来，框架与工具（LangChain 一类）只需要实现一次 OpenAI 适配就能对接整个生态。网络效应自我强化：越多人兼容，越没理由另起格式。

**3. Q：** 依赖兼容层做供应商路由，要注意什么？
**A：** 把「格式兼容」当作传输层的最低要求，在上面自己补一层能力协商：哪些端点支持 strict、哪些支持并行工具调用、流式切片粒度如何，逐项验证后写进供应商配置；对 429 与 529 类过载错误按端点分别设重试与熔断，见 [[7.外部依赖保护与服务级熔断]]。
