# LLM API 总览

建这个目录的原因：LLM API 是 Agent 项目最底层的外部依赖，多轮拼接、函数调用、流式、prompt caching 这些机制是面试讲 Agent 工程时的地基口径。当前（2026-09）三家主流 API 处于三种状态：Chat Completions 是事实上的行业格式标准（大量第三方服务兼容它），Responses 是 OpenAI 官方推荐的新一代 API（Chat Completions 未弃用但新能力优先落在 Responses），Anthropic Messages 是另一套独立设计（system 独立字段、content blocks、显式 thinking）。三家的字段名和往返细节容易混，需要一处按官方文档逐条对齐的笔记。

口径基线：OpenAI 侧以 developers.openai.com 的迁移指南与 API reference 为准，Anthropic 侧以 platform.claude.com 的 API 文档为准，均为 2026-09-08 抓取。行业兼容生态的观察也以该日期为准。

每个板块一个编号子目录，总览留在本目录根上；笔记文件名保留「板块号.序号」前缀（如 `2.3`）。

## 搬运工作流

1. 来源分级：OpenAI 官方文档（developers.openai.com 的 guides 与 API reference）> Anthropic 官方文档（platform.claude.com）> 官方博客；小博客与社区帖只作线索，不作口径来源。
2. 给 URL 或贴原文，提取后归入对应板块，整理成概念笔记：frontmatter（tags、类型: 概念笔记、状态）→ 概念讲解 →「实践例子」callout → 边界问答。
3. 概念讲解只写 API 本身；项目对照只进 callout，一到两句加链接。
4. 涉及版本演进时标明时间点；已弃用参数必须带弃用状态与替代写法，不写成当前可用能力；具体模型名点到为止，以字段与机制为主。
5. 笔记落盘后回本文勾选清单；粒度有变同步改清单。
