# HTTPS 与 TLS：加密握手与证书

## 明文 HTTP 差什么

HTTP 报文是明文，从客户端到服务端经过的任何机器（Wi-Fi 接入点、运营商路由、企业代理）都能完整看到并改掉内容。三个风险各对应一件事：窃听——`Authorization` 头里的 API key 裸奔；篡改——内容没有完整性校验，中间人可以改了再转发；冒充——客户端没有手段验证「回话的确实是这个域名的主人」，DNS 被劫持时就会连到假服务器。TLS（Transport Layer Security，传输层安全）就是补这三件事的协议，HTTP over TLS 即 HTTPS，默认端口 443（明文 HTTP 是 80）。现行主流版本 TLS 1.3（RFC 8446，2018）。

## 两类加密的分工

密码学的两种加密 HTTPS 都用，各干一件事。非对称加密：公钥加密只有配对的私钥能解，私钥签名可用公钥验证——慢（比对称慢几个数量级），但能解决「没见过面的双方怎么建立信任」。对称加密：双方共享同一把密钥加解密——快，适合加密全部数据，问题是这把密钥怎么安全地交给对方。TLS 的设计由此而来：非对称只在握手阶段用于身份验证与密钥交换，双方算出共享的会话密钥后，全部应用数据走对称加密。

## TLS 1.3 握手

```text
客户端                                        服务端
  | -- ClientHello -----------------------→ |  我支持这些加密套件与曲线参数
  | ←- ServerHello + 证书 + 签名验证 -------- |  选这套；证书证明我是该域名的服务器
  |    （客户端验证证书链到系统内置的根 CA）      |
  | -- ECDHE 密钥交换参数 -----------------→ |  双方各自算出相同的会话密钥
  | ←- Finished（会话密钥加密的确认）---------- |  握手完成，共 1 个往返
  | ═══════ 之后全部应用数据对称加密传输 ═════ |
```

TLS 1.3 一次往返（1-RTT）完成握手，TLS 1.2 需要两次。密钥交换用 ECDHE（临时椭圆曲线 Diffie-Hellman）：会话密钥由双方每次临时生成的参数算出、不落盘，服务端私钥将来泄露也解不开历史流量，这个性质叫前向保密（forward secrecy）。握手之上还叠着 TCP 的三次握手（[[2.TCP 连接：握手、可靠传输与长连接]]），这就是连接复用省时间的地方：省的是 TCP 加 TLS 两段协商。

## 证书与 CA

握手里的证书解决冒充问题：证书 = 域名 + 服务器公钥 + 权威机构（CA，Certificate Authority）的签名。客户端的操作系统与浏览器内置一批根 CA 公钥，收到证书后逐级验证签名链，链到受信任的根 CA 且域名匹配才继续。自签证书（自己给自己签名）没有可信链，客户端默认拒绝——开发环境抓包时手工信任抓包工具的根证书，本质是把它加进这条信任链。附带一个细节：握手时客户端在 ClientHello 里带上目标域名（SNI，Server Name Indication），因为一个 IP 可以托管多个域名的证书，服务端要按域名挑选该回哪张。

## 对 LLM API 意味着什么

API key 等于钱，它的安全性以 TLS 为前提：key 放在 `Authorization` 或 `x-api-key` 头里，明文 HTTP 下任何中间节点直接读走；HTTPS 下这些头在 TLS 密文里，公网路径不可见。三家 API 全部强制 HTTPS。放置顺序的约定也由此解释：key 不进 URL（URL 落代理与服务器日志）、不进请求体（应用层日志常把体整段记下来）、只进请求头——与 [[1.1 LLM API 的共同形态：endpoint、鉴权与请求骨架]] 的鉴权口径衔接。

> [!example] 实践例子
> 模型网关对三家供应商的调用全部走 HTTPS，key 只出现在请求头里，公网传输段的保密性由 TLS 保证（鉴权口径见 [[1.1 LLM API 的共同形态：endpoint、鉴权与请求骨架]]）；网关的封装设计见 [[11.代码级逻辑：一次 LLM 调用如何装配上下文]]。

## 边界问答

**1. Q：** 抓包工具能看到 HTTPS 明文，TLS 白加密了吗？
**A：** 那是主动交出去的信任：把抓包工具的根证书装进系统信任库，它就成了这条链路上的受信 CA，对经过它的流量做中间人解密。TLS 防的是未经信任的第三方，不防客户端自己批准的中间人，企业代理同理。

**2. Q：** 证书过期、域名不匹配会怎样？
**A：** 握手直接失败，连接建不起来（浏览器报证书错误，SDK 抛 SSL 异常）。证书设有效期是设计要求，用于限制私钥泄露的影响窗口；运维上靠自动续期（Let's Encrypt 的 ACME 协议这套路）保证不过期。

**3. Q：** 前向保密为什么重要？
**A：** 会话密钥每次连接临时算出、用完即弃。没有它（旧式 RSA 密钥交换），攻击者录下今天的密文，将来拿到服务器私钥就能回溯解密全部历史流量；有 ECDHE，私钥泄露只影响之后的连接，历史流量仍然安全。
