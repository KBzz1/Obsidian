# 复杂度分析：大 O 与常见复杂度阶

## 大 O 在量什么

时间复杂度度量的是「输入规模增长时，操作次数怎么跟着涨」，大 O 记号取增长趋势的主项、扔掉常数与低阶项——3n² + 5n 记作 O(n²)，因为 n 大时 n² 项主导。这样度量有两个动机：一是与机器解耦，同一算法在快慢机器上差常数倍、不差阶数；二是选型关心的不是 100 条数据谁快，而是百万条时谁先跑完。常见的阶从小到大：

```text
O(1)       与 n 无关                  哈希表等值查找、数组下标访问
O(log n)   n=10⁶ 时约 20 步           二分查找、B+ 树、跳表
O(n)       全量过一遍                 线性扫描、单层循环
O(n log n) n=10⁶ 时约 2×10⁷ 步        归并/堆排，比较排序的下限
O(n²)      n=1000 时 10⁶ 步           冒泡/选择/插入，双重循环
O(2ⁿ)      n=30 已上十亿              子集枚举、朴素递归斐波那契
O(n!)      n=10 已三百多万            全排列枚举
```

对数阶值得单独记：每一步把问题规模砍半（或砍成几分之一），n 翻倍只多一步操作。这个直觉贯穿二分查找、B+ 树导航、跳表查找——工程里最值钱的一档复杂度。

## 怎么估算：循环与递归

循环看嵌套层数与每层的收缩方式：单层遍历 O(n)；两层独立嵌套 O(n²)；每轮把区间折半（二分）是 O(log n)；「外层 n、每层内部再 log n」（逐元素做一次折半操作，如给每个数做二分定位）是 O(n log n)。递归看递归树：总代价 = 节点数 × 每节点工作量。朴素斐波那契 f(n) = f(n-1) + f(n-2) 展开成深度 n 的二叉树，节点数 O(2ⁿ)；归并排序每层合并总工作量 O(n)、共 O(log n) 层，总计 O(n log n)。

递归复杂度有现成的判别工具——主定理（master theorem），处理 T(n) = aT(n/b) + O(nᵈ) 形态的递归（a 个规模 n/b 的子问题，合并代价 nᵈ）：a > bᵈ 时叶子主导，O(n^(log_b a))；a < bᵈ 时根主导，O(nᵈ)；相等时 O(nᵈ log n)。代两个例子验证：归并排序 a=2、b=2、d=1，a = bᵈ，得 O(n log n)；二分查找 a=1、b=2、d=0，同样相等，得 O(log n)。面试不需要背证明，报得出这三种结果即可。

## 空间复杂度与均摊

空间复杂度同一个口径：额外开的辅助数组算进去，递归调用的栈深度也算。原地排序 O(1) 空间，归并排序要 O(n) 辅助数组，快排平均 O(log n) 的递归栈。均摊分析（amortized）处理「单次操作偶尔贵、总体便宜」的情况，算法是把一段时间的总代价摊到每次操作上：动态数组 append 多数次 O(1)，偶尔触发扩容拷贝 O(n)，均摊下来 O(1)；哈希表扩容、跳表掷骰子上层，都是同一个模式。

## 边界问答

**1. Q：** 大 O 为什么忽略常数？常数不重要吗？
**A：** 阶数决定规模增长时的胜负，常数决定同阶时的快慢，两者都要管但顺序固定：先看阶，再调常数。快排与归并同为 O(n log n)，快排常数小、顺序访问缓存友好，实际更快；小数组（十几个元素）上 O(n²) 的插入排序反而最快——Timsort 与快排的工程实现都在小段切换到插入排序，就是在同阶之内换常数更小的算法。

**2. Q：** O(log n) 的底数去哪了？
**A：** 换底只差常数因子：log₂n 与 log₁₀n 相差约 3.32 倍，大 O 里统一写 O(log n)。B+ 树扇出上千，等于对数的底数极大、常数极小——这正是它比二叉树矮的原因，也是「同为对数阶、工程表现差很远」的例子。

**3. Q：** 最好、最坏、平均复杂度，面试报哪个？
**A：** 默认报最坏。两个高频例外要主动补平均：快排最坏 O(n²)（已有序输入取首元素做 pivot 时递归退化）、平均 O(n log n)；哈希表最坏 O(n)（键全冲突）、平均 O(1)。说清「默认最坏、这两个补平均」即可。

**4. Q：** 遍历一次链表是 O(n)，遍历一次哈希表也是 O(n)，为什么体感差这么多？
**A：** 复杂度只管阶数，缓存与内存局部性是阶数之外的现实因素：链表节点散落、指针跳转每次都可能 cache miss，连续数组的顺序扫描快得多。算法选型先比阶，实现优化再看局部性。
