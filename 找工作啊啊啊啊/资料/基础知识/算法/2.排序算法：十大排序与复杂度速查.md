# 排序算法：十大排序与复杂度速查

## 两族排序：比较的与非比较的

排序分两族。比较排序只靠「两元素比大小」决定次序：冒泡、选择、插入、希尔、快排、归并、堆排；这族有理论下限 O(n log n)——n 个元素有 n! 种排列，一次比较最多区分两种情况，定位唯一排列至少要 log₂(n!) ≈ n log n 次比较。非比较排序绕开比较、按值直接定位：计数、桶、基数，能做到 O(n) 级，代价是对数据有假设（整数、值域有限、分布均匀）。

## 比较排序速查

| 排序 | 平均 | 最坏 | 最好 | 空间 | 稳定 | 一句话机制 |
|---|---|---|---|---|---|---|
| 冒泡 | O(n²) | O(n²) | O(n) | O(1) | 稳 | 相邻逆序则交换，每轮浮出一个最大值到尾部 |
| 选择 | O(n²) | O(n²) | O(n²) | O(1) | 不稳 | 每轮选剩余最小值，换到已排序段末尾 |
| 插入 | O(n²) | O(n²) | O(n) | O(1) | 稳 | 把新元素逐个前移，插进已排序前缀的合适位置 |
| 希尔 | 约 O(n^1.3) | O(n²) | — | O(1) | 不稳 | 按间隔分组做插入排序，间隔逐轮减到 1 |
| 快排 | O(n log n) | O(n²) | O(n log n) | O(log n) | 不稳 | 选 pivot 分区，小的去左大的去右，递归两侧 |
| 归并 | O(n log n) | O(n log n) | O(n log n) | O(n) | 稳 | 递归折半到单元素，有序子数组两两合并 |
| 堆排 | O(n log n) | O(n log n) | O(n log n) | O(1) | 不稳 | 建堆后反复取堆顶，末元素补位再下沉 |

快排的空间 O(log n) 是递归栈的平均深度；希尔的平均复杂度依赖间隔序列，O(n^1.3) 是经验值。

三个高频追问点。**插入排序为什么最好 O(n)**：输入基本有序时每个元素只前移一两步就位，一轮近线性——这个性质被 Timsort 利用。**稳定性是什么、谁稳定**：值相等的元素排序后保持原相对次序；冒泡（只交换逆序对）、插入（相等即停）、归并（合并时相等取左）稳定，选择（最小值与前面交换会跳过中间相等元素）、快排（分区交换跨越相等对）、堆排（堆顶弹出打乱次序）不稳。稳定性的实际意义在对象排序：先按次要键排一遍、再按主要键稳定排一遍，主要键相同的仍按次要键有序；不稳定排序做同样的事，得把所有字段写进比较器一次比完。**快排最坏何时出现、怎么规避**：pivot 选择不当（如已有序数组固定取首元素），每次分区都极不均衡，递归退化成 O(n²)；规避靠随机取 pivot 或三数取中，工程实现再叠两条——小段切换插入排序、递归过深切换堆排兜底（C++ 标准库的内省排序就是这个组合，保证最坏 O(n log n)）。

工程里实际跑的排序是混合实现：Python 的 sorted 与 list.sort 用 Timsort——归并与插入的混合，先识别输入里本来就有的连续有序段（run），run 内天然有序、run 之间归并，最好 O(n)（已有序输入）、最坏 O(n log n)、稳定；Java 对象排序同为 Timsort，基本类型用双轴快排。面试答「内置排序是什么」就指到这两个。

## 非比较排序：计数、桶、基数

计数排序：值域 0–k 的整数，统计每个值的出现次数，按值域顺序输出——O(n + k)，k 与 n 同量级时就是 O(n)。桶排序：值域均匀时把元素散进 m 个桶，桶内各自排序（通常插入）再拼接，期望 O(n + m)；分布倾斜、元素挤进少数桶时退化。基数排序：按位从低到高做 d 轮稳定排序（每轮通常计数），总 O(d·(n + k))。三者共同前提是「值能当数组下标用或能按位拆」；排自定义对象（只有比较器、没有数值语义）只能回到比较排序族。

## Top-k：只要前 k 名就别全排序

从 n 个元素里取最大/最小的 k 个（k 远小于 n），全排序 O(n log n) 是浪费，两条正路。堆：手握一个 k 大小的小顶堆（堆顶是这 k 个里最小的），新元素比堆顶大就弹顶入新，全程 O(n log k)、还天然支持流式数据来一个算一个。快速选择（quickselect）：借快排的分区，每轮只递归包含第 k 大的那一侧，平均 O(n)（最坏 O(n²)，随机 pivot 规避）。堆（heap）本身值得会写：数组隐式表示的完全二叉树，i 的孩子在 2i+1 与 2i+2，插入上浮、取顶下沉都是 O(log n)。

```python
import heapq

top = heapq.nlargest(10, scores)     # 前 10 大：内部维护 k 大小的小顶堆
heapq.heappush(heap, item)           # 入堆并上浮，O(log n)
heapq.heappop(heap)                  # 弹出最小元素并下沉补位，O(log n)
```

Top-k 是跨领域的通用问题形态：向量检索要的也是「与查询最近的 k 条」（[[2.ANN 检索：HNSW 与召回率权衡]]），那边先用索引把候选从百万缩到一小撮，再精确比较取 k——同一道 top-k，工程版把「n 很大」拆给了索引层。

> [!example] 实践例子
> 项目代码与日常脚本里的 sorted() / list.sort() 就是 Timsort，无需手写排序；真正手写的场景只剩面试白板。检索链路里 rerank 后取前 k 条结果，对应堆或快选的 top-k 形态（[[2.ANN 检索：HNSW 与召回率权衡]]）。

## 边界问答

**1. Q：** 为什么比较排序快不过 O(n log n)？
**A：** 决策树论证：n 个元素有 n! 种可能排列，一次二值比较最多把候选排列砍半，区分到唯一一种至少要 log₂(n!) ≈ n log n 次比较。计数/桶/基数不比较、按值直接定位，不受这条下限约束——但它们的前提（值可下标化、分布有假设）本身就是代价。

**2. Q：** 被问「哪个排序最好」怎么答？
**A：** 按约束答而不是报一个名字：要稳定且最坏有保证，归并；内存紧、要原地，堆排；平均最快、缓存友好，快排（配随机 pivot）；基本有序或极小数组，插入排序；工程实践直接用语言内置的混合排序（Timsort、内省排序），它们已经在各段上替你做了这些选择。

**3. Q：** 堆排和快排同为 O(n log n)，为什么实际快排更快？
**A：** 常数与局部性：快排分区是顺序扫描，缓存友好；堆的上浮下沉在 i 与 2i+1 之间跳，访问跨度大、cache miss 多。加上堆排每取一个顶都要完整下沉一轮。阶相同、常数与访问模式的差距在真实数据上拉开数倍。

**4. Q：** 什么时候手写堆、什么时候用快选？
**A：** 数据能全量进内存且要一次出结果，快选平均 O(n) 更快；数据是流式的、或 k 很小且只要维护前 k 名（排行榜、实时 top-k），堆更合适——不必等数据到齐。Python 里 heapq 开箱即用，快选需要手写分区。
