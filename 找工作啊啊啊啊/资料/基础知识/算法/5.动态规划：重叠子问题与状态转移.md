# 动态规划：重叠子问题与状态转移

## DP 是什么

动态规划（dynamic programming，DP）把问题拆成子问题、每个子问题只算一次、结果存表复用。一个问题能用 DP 解，要同时满足两个结构性条件。重叠子问题：递归展开后同一个子问题反复出现——朴素递归算斐波那契 f(5) 时，f(3) 被算两次、f(2) 三次，重复随深度指数放大，这是 DP 存表的价值来源。最优子结构：原问题的最优解由子问题的最优解拼出来——路径类问题里最短路径的子路径也是最短，这是转移方程能成立的前提。工程上还有一条无后效性要求：某阶段的状态一旦确定，之后的演化不再受「怎么到达这个状态」影响——状态定义必须把会影响未来的历史信息封装完。三个词就是 DP 八股的标准答案骨架。

从暴力到 DP 的三步，用爬楼梯走一遍（每次上 1 或 2 阶，问上 n 阶有多少种走法）：

1. 暴力递归：f(n) = f(n-1) + f(n-2)，最后一步要么跨 1 阶（来自 n-1）要么跨 2 阶（来自 n-2），两类走法不重不漏。重叠子问题让它 O(2ⁿ)。
2. 记忆化递归（自顶向下）：算过的 f 存哈希表，重复调用直接取——O(n) 时间、O(n) 空间（表 + 递归栈）。
3. 递推（自底向上）：从 f(1)、f(2) 起往上填表，只留两个滚动变量——O(n) 时间、O(1) 空间。

```python
def climb(n):
    a, b = 1, 1                    # a=f(0)、b=f(1)：滚动变量存最近两项
    for _ in range(2, n + 1):      # 自底向上逐级递推
        a, b = b, a + b            # 转移：f(i) = f(i-1) + f(i-2)
    return b                       # b 滚到 f(n)
```

记忆化与递推是同一个 DP 的两种实现：前者贴近思考过程、只算真正用到的子问题；后者没有栈深问题、能滚动压缩空间，但要自己保证按依赖顺序枚举状态。

## 状态设计与题族速查

DP 做题的实际难度不在写代码，在「定义状态」和「找转移方程」。套路是把进度信息定成状态维度——到第 i 个元素、前 i 件物品、容量 j、两串各自的前 i / 前 j 个——f 的含义用一句话写死（最大值？方案数？布尔可行？），转移方程回答「f(i) 从哪些更小的子状态、经什么选择推过来」。常见题族按状态形态分：

| 题族 | 状态定义示例 | 代表题 |
|---|---|---|
| 线性 DP | f(i) = 考虑前 i 个元素时的最优 | 爬楼梯、打家劫舍、最长上升子序列 |
| 背包 | f(i, j) = 前 i 件、容量 j 时的最优 | 0-1 背包、完全背包、分割等和子集 |
| 双序列 | f(i, j) = 两串前 i、前 j 个的最优 | 编辑距离、最长公共子序列 |
| 区间 DP | f(i, j) = 区间 [i, j] 上的最优 | 戳气球、最长回文子串 |
| 状态机 | f(i, s) = 第 i 天处于状态 s 的最优 | 买卖股票系列（持有/不持有） |

背包单独说清，它是追问密度最高的题族。0-1 背包的转移：f(i, j) = max(不选第 i 件，选第 i 件) = max(f(i-1, j), f(i-1, j - w[i]) + v[i])——不选则容量不变继承上一层，选则腾出 w[i] 的容量换 v[i] 的价值。压成一维数组 f(j) 时，容量 j 必须倒序枚举：正序会先更新小的 j，导致算 f(j) 时用到的 f(j - w[i]) 已是「选过第 i 件」的值，等于一件物品选了两次。完全背包（每件不限次数）正好相反，要正序——同一件允许重复选，正是那个「错误」语义。倒序 0-1、正序完全，这是背包的高频追问。

## 与回溯、贪心的分界

回溯：要所有解、或方案本身要列出来，就用回溯枚举（[[4.递归与回溯：什么时候用回溯]]）；只要最值或方案数，且子问题重叠，就用 DP 存表。同一个「凑硬币」问题，问「最少几枚」是 DP，问「列出所有凑法」是回溯。

贪心：每步取局部最优、不回头。当问题具有贪心选择性质——局部最优能拼成全局最优——贪心 O(n log n) 打赢 DP 的 O(n·k)；性质不成立时贪心给出错误答案。经典反例是任意面额的硬币找零：面额 {1, 3, 4} 凑 6，贪心每次拿最大面额得 4+1+1 三枚，DP 得 3+3 两枚——面额不是标准系统（1、5、10、50 这种倍进位）时贪心不保证对。两者的关系可以一句话收：贪心是 DP 的特例，当最优子结构强到「每步的最优选择与后续无关」时，DP 转移里的 max 退化成唯一的贪心选择。面试稳妥路径：先试贪心，找得到反例就回 DP。

分治：子问题互不相交（归并的左右两半），无须存表；DP 的子问题相交才有存表的价值。这条也解释了归并排序为什么叫分治不叫 DP。

> [!example] 实践例子
> 项目本身不踩 DP，它的主战场是面试算法环节。思想上最近的工程同构是缓存：记忆化 = 给重复子问题的结果建缓存、命中就不重算，与 [[4.缓存穿透、击穿与雪崩]] 的 Cache-Aside 是同一个「空间换时间」思想在不同层的应用。

## 边界问答

**1. Q：** 记忆化递归和递推，面试写哪个？
**A：** 都是对的 DP。先讲清状态定义与转移方程（这才是考点），实现选顺手的：记忆化从原问题出发、只算用到的子问题，代价是递归栈（Python 默认深度约 1000，深递归有栈溢出风险）；递推无栈深问题、可滚动压缩空间，但要自己排好枚举顺序。

**2. Q：** DP 和贪心怎么选？
**A：** 先问「局部最优是否必然拼出全局最优」。能证明（交换论证、反证）就用贪心，快一个量级；证明不了、或题目要方案数/可行性判定，就用 DP。判据拿不准时的实操：写个贪心找小规模反例（暴力对拍），有反例立刻转 DP。

**3. Q：** 怎么判断一道题是 DP 题？
**A：** 三个信号叠加：问最值、方案数或可行性（不是要列出所有方案）；决策分阶段，当前选择改变后续可选集；把暴力递归写出来发现大量重叠子问题。命中前两条时先快速试一下贪心有没有反例，没有就上 DP。

**4. Q：** 状态定义不出来怎么办？
**A：** 从暴力递归反推：递归函数的参数就是状态维度的候选，逐个砍掉「不影响后续决策的历史细节」（这正是无后效性对状态的要求），剩下的就是状态；转移方程就是递归的调用关系。定好后再考虑压维度——滚动数组降一维的前提是转移只依赖上一行/上几项。

**5. Q：** DP 为什么快？省掉的到底是什么？
**A：** 省掉的是重复求解同一个子问题。朴素递归的递归树里同一子状态展开成整棵子树，记忆化后每个子状态只算一次、其余访问都是查表——O(2ⁿ) 到 O(n) 的差距不是算法换了思路，是同一张递归树被压掉了重复子树。
