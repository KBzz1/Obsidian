# 二分查找与双指针

## 二分查找：有序就折半

二分查找的前提是数组有序，每步与中点比较排除一半区间，O(log n) 时间、O(1) 空间。难点不在思想在边界：区间定义（左闭右闭 [l, r] 还是左闭右开 [l, r)）、收缩方向、循环条件三者必须配套，错一个就死循环或漏解。标准版与左边界版对照，体会两套配套约定：

```python
def bsearch(nums, target):              # 找任意一个等于 target 的下标
    l, r = 0, len(nums) - 1             # 闭区间 [l, r]，两端都取得到
    while l <= r:                       # 空区间是 l > r，所以循环带等号
        mid = l + (r - l) // 2          # 防溢出写法，等价 (l + r) // 2
        if nums[mid] == target:
            return mid                  # 命中即返回
        if nums[mid] < target:
            l = mid + 1                 # 目标只可能在右半
        else:
            r = mid - 1                 # 目标只可能在左半
    return -1

def bsearch_left(nums, target):         # 找第一个 >= target 的位置
    l, r = 0, len(nums)                 # 左闭右开 [l, r)，r 取不到
    while l < r:                        # 空区间是 l == r，循环不带等号
        mid = l + (r - l) // 2          # 同样的防溢出写法
        if nums[mid] < target:
            l = mid + 1                 # mid 及其左侧全部排除
        else:
            r = mid                     # mid 可能就是答案，不能排除
    return l                            # 两端收敛到同一处即左边界
```

两版的差异来自目标不同：标准版找到任一命中就返回；左边界版要「第一个满足条件的位置」，命中也不返回、继续往左压，所以用左闭右开区间、收缩时不越过 mid。左边界版即 Python 标准库 bisect.bisect_left，右边界 bisect_right 同理往右压。判重复元素个数、找插入位置、找第一个/最后一个满足某条件的位置，都用边界版而不是标准版。

## 二分的推广：旋转数组与答案空间

旋转数组（有序数组从某处断开轮转，如 [4,5,6,1,2,3]）仍可二分：取 mid 后，[l, mid] 和 [mid, r] 至少一半是内部有序的——判断哪半有序、再看 target 是否落在有序半边的值域内，在则收缩到这半、不在则收缩到另半。单调性被「打断成两段」，但每轮仍能排除一半，O(log n) 保住。

答案空间二分是更一般的形态：题面没有数组，但「最小的 x 使 f(x) ≥ t」里的 f 单调（x 越大 f 越大），就把 x 的取值范围当有序数组折半。典型题：吃香蕉的最小速度、按天运货的最低运力——速度快/运力大则天数少，单调成立，对「速度」二分而不是对数组。识别信号就一句：求「最小的满足条件的值」，且条件随该值单调变化。

## 双指针：对撞、快慢与同向

双指针指两个下标配合移动、把双重循环的 O(n²) 压成 O(n)，按移动方向分三形态。对撞指针：从两端向中间收缩，适用有序数组的两数之和为目标值——和小了左指针右移、大了右指针左移，错过即无解。快慢指针：同向不同速，链表判环（快慢相遇则有环）、找链表中点（快到尾时慢恰在中点）。同向指针的成熟形态是滑动窗口，单独说。

## 滑动窗口：连续区间的 O(n)

滑动窗口维护一段连续区间 [l, r]：右端不断扩张，指标越界时左端收缩，直到指标回到合法范围再继续扩张。以最长无重复子串为例：右端逐字符进窗，遇到窗口内已有的字符，左端收缩到该字符上次出现位置之后，全程每个字符最多进出窗口各一次，O(n)。适用判别两条：题目问「连续子数组/子串」的最优指标；窗口扩张或收缩时指标单调变化（右端进元素指标单调变差/变好），收缩时能 O(1) 维护指标。若指标不单调（如含负数的子数组和、窗口内要动态排序），窗口失效，换前缀和或别的做法。

前缀和是连续区间问题的另一件工具：prefix[i] = 前 i 项之和，任意区间和 O(1) 取差得到；配上哈希表记录「每个前缀和首次出现位置」，「和为 k 的子数组个数」这类题也是 O(n)——遍历时查 prefix[i] - k 之前出现过几次。

> [!example] 实践例子
> 项目本身不踩二分与双指针，这层是面试基础。工程上的真实形态是「有序数据上定位」：时间线/日志按时间排序后二分定位区间，Python 里就是 bisect.bisect_left。数据库索引每一层的键内定位也是二分——B+ 树把「下一层走哪个孩子」做成多路二分（[[1.MySQL 索引：B+ 树与查询优化]]）。

## 边界问答

**1. Q：** 为什么写 mid = l + (r - l) // 2？
**A：** (l + r) 在 32 位整数下可能溢出，先减后加不会。Python 整数无限精度，写 (l + r) // 2 不出错，但 Java/C++ 面试必须写防溢出版本——这是这道八股的经典追问点，答「Python 不怕、C++/Java 要防」即可。

**2. Q：** 二分一定要数组有序吗？
**A：** 要的是可判定的单调性，数组有序只是其一。旋转数组是断成两段的弱有序；答案空间上 f(x) 单调也行。完全无序的数组找特定值，二分无能为力——哈希 O(n) 建表 O(1) 查，或先排序再二分（O(n log n)，多次查询才摊得回来）。

**3. Q：** 滑动窗口什么时候不能用？
**A：** 窗口指标不随扩张/收缩单调变化时。含负数的「和恰好为 k」没有单调性（扩张和可能变小），改前缀和 + 哈希；窗口指标依赖排序结构（中位数）时窗口无法 O(1) 维护，改对顶堆。判别动作在写代码前：先问「右端进一个元素，指标变化方向固定吗」。

**4. Q：** 双指针为什么能替代双重循环？
**A：** 前提是「指针的移动方向能由当前比较结果唯一确定」，即每步排除一批候选而无须逐个试——对撞指针每步排除一端外的所有配对，滑动窗口左端只前进不回头，各元素进出一次。没有这种单调性（两数之和的数组无序时），指针不知道往哪走，只能先排序或用哈希。
