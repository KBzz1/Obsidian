# 递归与回溯：什么时候用回溯

## 递归与分治

递归是函数调用自身，正确性靠两件事撑住：基准情形（base case，不再递归的最小子问题，直接给答案）与规模收缩（每次调用都朝基准走，否则无限递归）。写递归先定三件事，顺序固定：函数含义（输入输出的约定，一句话说清这个函数算什么）、基准情形、递归关系（大问题怎么拆成更小的同类问题）。分治（divide and conquer）是递归的一种用法：把问题切成互不相交的子问题，各自求解后合并结果——归并排序折半再合并、快排分区再递归，都是分治（见 [[2.排序算法：十大排序与复杂度速查]]）。

## 回溯：决策树上的试探与撤销

回溯（backtracking）是系统枚举所有候选解的递归框架。它把「构造一个解」的过程看成一棵决策树：每个节点是一次选择，从根走到叶是一个完整候选；走到某处发现违反约束或已凑出一个解，就撤销最近的选择、退回上一层换下一个分支——「试探之后撤销」就是回溯这个名字的字面来源。通用模板：

```python
def backtrack(path, choices):          # path 已做的选择；choices 当前可选集
    if 到达结束条件:                   # 叶子：收集或返回
        result.append(path[:])         # 拷贝快照，防后续修改污染
        return
    for c in choices:                  # 枚举本层的每个候选
        if 不满足约束(c):              # 剪枝：无望的分支直接跳过
            continue
        path.append(c)                 # 做选择
        backtrack(path, 下一步候选集)  # 进入下一层
        path.pop()                     # 撤销选择，回到本层试下一个

模板要紧的是最后三行的「做选择 → 递归 → 撤销」三连：递归返回后 path 必须恢复原状，上一层才能正确地试下一个分支。忘写 path.pop()（或在收集答案时不拷贝）是这类题最常见的两类 bug。

回溯的复杂度天然是指数级——子集问题 2ⁿ、排列问题 n!，回溯不消除这一点，只做两件事：用约束剪掉明确无望的分支（剪枝），在到达叶子的路径上收集答案。

## 怎么判断这道题用回溯

四个特征，命中越多越指向回溯：

1. 要「所有」解而不是一个最优解——所有子集、全排列、所有组合、所有可行方案。求一个最优值优先考虑贪心或 DP；要把每个方案列出来，基本就是回溯。
2. 解是逐步构造出来的序列或集合，每一步从候选里挑一个，挑错能撤销重来。
3. 约束在中间过程就能判定——部分和已超限、棋盘格已被占，走到一半就知道这枝没戏，可以剪。
4. 输入规模小，n ≤ 20 上下的量级，指数复杂度可承受。这既是出题的提示（为什么这题 n 这么小），也是硬边界（n 上三位数时回溯必超时，必须换 DP 或数学做法）。

题型对号入座：子集与组合（如「n 个数里选 k 个」）——候选从「当前位置之后」选，天然不回头、不重复；排列——候选是「还没用过的」全量，用 used 数组标记；N 皇后与数独——棋盘加约束剪枝，剪枝就是全部优化空间；括号生成、分割回文串——构造序列 + 中途判定。输入含重复元素要去重：先排序，同一层里值相同的候选只试第一个（跳过「与前一个相等且前一个不是本层刚撤销的」分支），保证同层不重、同枝可重。

## 与 DFS、DP 的分界

回溯与 DFS 的关系：DFS（深度优先搜索）是图的遍历策略（见 [[6.树与图的遍历：DFS、BFS 与拓扑排序]]），回溯是把解空间（决策树）当成图来做 DFS——遍历的是逻辑上的树而不是显式的图，边是「选择」，访问动作是「做选择 + 撤销」。区别在目的：图的 DFS 要求每个点恰访问一次；回溯在决策树上走，目的是收集满足条件的路径与叶子。

回溯与 DP 的分界线是重叠子问题：回溯枚举所有路径，相同子状态会被重复探索；当只要求最优值或方案数、且递归展开后同一子状态反复出现时，把「从状态 i 出发的答案」存成表，回溯就转成 DP——见 [[5.动态规划：重叠子问题与状态转移]]。一句话版：要方案列表用回溯，要最值或计数用 DP。

> [!example] 实践例子
> 健康管理项目不踩回溯。工程里最近似的形态是可撤销操作：数据库事务失败回滚（[[2.事务与隔离级别：锁与 MVCC]]）、编辑器撤销栈，共同点都是「记录怎么改的、错了退回去」。LangGraph 侧最近似的是时间旅行——从历史 checkpoint 拉起重放，相当于撤销之后的选择、换分支再试（[[2.3 时间旅行：get_state、update_state 与重放]]），但那是人工介入语义，不是执行引擎自动回溯。

## 边界问答

**1. Q：** 回溯就是 DFS 吗？
**A：** 回溯是 DFS 在解空间树上的应用，不是同义词。图的 DFS 关注遍历每个点一次，路径本身通常就是答案（连通性、判环）；回溯关注构造中的路径，靠「选择-撤销」维护 path，允许在叶子收集快照。面试答「回溯用 DFS 的方式搜索解空间」是安全口径。

**2. Q：** BFS 能代替回溯吗？
**A：** 求全部解时两者都是完备搜索，选型看形态：回溯（DFS 型）用递归栈，内存只要 O(深度)；BFS 逐层扩展，解树一宽队列就爆炸，但保证最先到达的是最浅解。要「最少步数/最少操作」的搜索用 BFS（无权最短路，见 [[6.树与图的遍历：DFS、BFS 与拓扑排序]]），要列举全部方案用回溯。

**3. Q：** 剪枝什么时候必须做？
**A：** 搜索规模超时限时。全排列裸搜是 n! 增长——n=12 已近 5 亿节点，不做约束剪枝不可行；N 皇后靠「列与对角线被占」的即时判定把树剪到可承受。剪枝通常不改最坏复杂度的阶，但能把实际搜索规模压几个数量级，这是回溯题优化的全部内容：更早判定、更强排除。

**4. Q：** 同一道题，回溯写出来超时，往哪转？
**A：** 三个方向按序检查：只要最优值不要方案列表——转 DP（重叠子问题存表，见 [[5.动态规划：重叠子问题与状态转移]]）；只判断可行/计数——也转 DP 或记忆化；有贪心性质（局部最优可拼全局）——转贪心。回溯保留给「必须列出所有方案」或「状态空间无重叠可剪」的场景。
