# 事件循环、协程与 await

## 进程与线程

进程是运行中的程序实例，线程是进程里实际执行代码的执行流。默认一个进程只有一条主线程，代码从头到尾一条线执行；也可以创建多条线程，由操作系统在它们之间快速切换，宏观上同时做多件事，同进程的线程共享同一块内存。asyncio 走另一条路线：只用一条线程，让代码在等待时主动让位，实现多个任务交错推进。

## I/O 等待与两条并发路线

网络服务处理一次请求的耗时里，真正占 CPU 的计算往往只有几毫秒，其余全是等 I/O：等数据库返回、等下游 HTTP 服务、等 LLM 生成——几秒到几十秒，期间 CPU 纯粹空转。如果一条线程串行处理请求，第二个请求必须等第一个请求的全部 I/O 结束才能开始，吞吐量不可接受。两种改法：

- 多线程：每个请求一条线程，一条线程等待时操作系统切换到别的线程。可用，但每条线程自带调用栈（内存 MB 级），几千并发就是几千线程，创建与切换都有成本；且线程之间任何两行代码之间都可能被切走，共享内存处处要加锁。
- asyncio：只用一条线程。代码执行到需要等待的地方主动挂起，线程转去推进其他任务，等结果到达再切回来继续。没有线程数量与切换的开销，也没有抢占式切换带来的处处竞态——切换只发生在代码里显式写出的 await 处。

## 事件循环

事件循环（event loop）是 asyncio 在这条线程上维护的调度循环，可以当作一名调度员，手里两份名单：

```text
就绪名单：可以继续执行的任务
等待名单：在等某个结果的任务（网络响应、数据库返回、定时器）

循环每一步：
1. 从就绪名单取一个任务，执行它的代码
2. 跑到它需要等待的位置（await），把它挂到等待名单
3. 回到第 1 步，执行下一个就绪任务
4. 某个等待的结果到达，把对应任务移回就绪名单
```

线程永远在执行有活可干的任务，不会停在某个任务的等待上空转。

## 协程与 await

`async def` 定义的函数是协程（coroutine）：调用它不执行代码，而是返回一个协程对象，交给事件循环调度。协程里的 `await` 是挂起点，语义是：

```text
await <可等待对象>
    我要等这个结果，现在拿不到
    → 挂起当前协程，控制权交还事件循环
    → 结果到达后，从这一行恢复执行，拿到结果值
```

典型的一次请求处理：

```python
async def handle(request):
    data = await load(request)       # 挂起点 1：等数据库返回
    answer = await call_model(data)  # 挂起点 2：等下游模型服务，几十秒
    await save(answer)               # 挂起点 3：等数据库写完
    return answer
```

## 多个请求如何交错

一条线程任意时刻只执行一个协程的代码，但几十个请求可以同时在途——各自停在某个 `await` 上等结果。两个请求交错推进的时间线：

```text
时间 ────────────────────────────────────────────→

请求 A：  查库 ─┐               ┌─ 结果到 ─ 写库 ─ 返回
                 └─ 等模型 ─────┘
请求 B：         └─ 查库 ─┬─ 等模型 ────┬─ 结果到 ─ 写库 ─ 返回
                           └（等结果）  ┘
线程：  跑A → A挂起 → 跑B → B挂起 → 跑其他/空闲 → 唤醒A → 唤醒B → …
```

这是并发不是并行：并发（concurrency）指多个任务交错推进，单线程也能做到；并行（parallelism）指多个 CPU 核同时执行，需要多进程或多线程。asyncio 只改善 I/O 等待型负载——等网络、等磁盘、等外部服务；纯计算型代码里没有 `await`，占着事件循环不让，谁都切不进来。

> [!example] 实践例子
> 健康管理项目的 Worker 用 asyncio 模型运行：单个进程一条线程处理多个用户的聊天请求，LLM 调用几十秒的等待正好让位给其他请求。切换只发生在 `await` 处，这同时决定了进程内锁的保护范围——只保护跨 `await` 的序列，见 [[2.asyncio.Lock 与协程间互斥]] 与 [[7.版本控制与并发]] 的「锁的定位」。

## 边界问答

**1. Q：** 单线程为什么能同时处理大量请求？
**A：** 请求的耗时几乎全在等 I/O，协程停在 `await` 上不占线程，线程只执行就绪的代码。并发上限取决于 I/O 等待能否重叠，而不是线程数量。

**2. Q：** CPU 密集型代码放进协程会怎样？
**A：** 纯计算代码没有 `await`，事件循环切不出去，该协程执行期间同进程所有协程一起卡住。重计算应放独立进程或独立服务。

**3. Q：** 两个 `await` 之间的代码会被其他协程插队吗？
**A：** 不会。切换只发生在 `await` 处，两个 `await` 之间是一段不可分割的执行。这是与多线程的根本差别：线程任何两行代码之间都可能被切走，协程只在显式写出的 `await` 处切换。也正因为如此，跨越 `await` 的检查-执行序列才需要异步锁保护，见 [[2.asyncio.Lock 与协程间互斥]]。
