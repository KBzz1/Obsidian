# 进程间通信：从管道到共享内存

## 为什么进程间通信要专门做

进程的虚拟地址空间互相隔离（机制见 [[2.进程与线程：内核视角与上下文切换]]）：A 进程里的任何地址只在 A 的页表里有意义，B 进程拿不到。要交换数据只能在内核里开中转——内核是所有进程共用的，双方都信任它。IPC（Inter-Process Communication，进程间通信）一族机制都从这一点出发：区别只在「数据放哪、拷几次、怎么同步」。

## 管道与消息队列

管道是 shell 里 `ps aux | grep python` 的那根竖线：内核里一段环形缓冲区（Linux 通常 64KB），一端写一端读，缓冲区满则写阻塞、空则读阻塞。它是半双工的字节流——数据像水流，读方拿到多少算多少，没有消息边界；匿名管道靠 fork 继承 fd 传递，所以只在父子等有亲缘关系的进程间可用，命名管道（FIFO）在文件系统里有个路径名，无亲缘的进程也能打开同一根。

消息队列换成内核里的消息链表：每条消息有类型和边界，读方可以按类型挑着取；队列独立于收发进程——写方退出消息仍在，直到显式删除或系统重启。管道和消息队列传数据都要两次拷贝：发送方用户态到内核一次，内核到接收方用户态一次。

## 共享内存、信号量与信号

共享内存把同一块物理内存映射进两个进程的地址空间，两边读写就像读写自己的内存。它是最快的 IPC：数据零拷贝，一次写入对方直接可见，通信本身不需要系统调用。代价是没有任何保护和次序——两个进程同时写同一位置就是数据竞争，必须配外部同步原语，标配是信号量（机制展开见 [[5.锁、信号量与死锁]]）：一个计数器加等待队列，P 操作申请（计数减一，不够就睡）、V 操作释放（加一，唤醒等待者），用来保证「我写完你再读」的次序。

信号量本身是同步工具，不传数据；真正叫「信号」（signal）的是另一样东西：内核或进程向目标进程发送的异步通知，只有一个编号没有载荷。`kill -9` 发的 SIGKILL 不可捕获不可忽略，进程当场终止；SIGSEGV（段错误）、SIGTERM（请求退出）、SIGINT（Ctrl+C）都是常见成员。信号适合「通知某事发生了」，不适合传数据。

## socket

管道与共享内存都限本机，socket 是通用件：全双工、有标准协议、跨机器，HTTP 与各类 RPC 都跑在它上面。本机场景它也有变体——Unix domain socket 不走网络协议栈，进程间在同一台机器上通过一个文件路径寻址互连，比绕回环地址的 TCP 快。分布式系统里跨进程通信的绝大多数就是 socket 上的应用协议。

六种方式并排：

```text
方式        数据拷贝   边界与同步               适用
匿名管道    两次       字节流，半双工，需亲缘     父子进程流式传递
命名管道    两次       同上，任意进程可用        本机任意两进程
消息队列    两次       消息有类型与边界          小量有格式的消息
共享内存    零次       无同步，需配信号量        大量、高频的数据交换
信号        无         异步事件编号，无载荷      通知与控制
socket      视协议     双向，跨主机             通用，分布式默认
```

> [!example] 实践例子
> PostgreSQL 是共享内存路线的活样本：一连接一进程，backend 进程共用的缓冲池与锁表放在共享内存里，数据交换零拷贝、配锁表同步，见 [[5.PostgreSQL 架构：进程模型、WAL 与后台进程]]。健康管理项目的多个 Worker 之间不共享任何内存——它们是可能分布在不同机器上的独立进程，协作走 socket 上的 HTTP 与数据库：「两个 Worker 抢同一个活跃任务」不靠进程间信号量，而是落到 PostgreSQL 的部分唯一约束上，见 [[7.版本控制与并发]] 的「单个活跃任务的数据库约束」。用数据库当跨进程协调点，是应用层对 IPC 的常见替代。

## 边界问答

**1. Q：** 最快的 IPC 为什么是共享内存？
**A：** 数据不经内核中转：写入即可见，每次通信零拷贝、零系统调用。管道与消息队列每条消息都要两次拷贝并陷入内核。代价是没有同步，必须配信号量。

**2. Q：** 多个 Worker 协作用共享内存行不行？
**A：** 前提就不成立：共享内存要求进程在同一台机器上，Worker 是多机部署的独立进程。即使同机，抢任务的正确性也要数据库唯一约束兜底，见 [[7.版本控制与并发]]。

**3. Q：** 管道和消息队列差在哪？
**A：** 管道是无边界字节流，读多少算多少，且匿名管道要求亲缘进程；消息队列每条消息有类型与边界、可按类型取，不依赖亲缘关系，写方退出后消息仍留在内核。
