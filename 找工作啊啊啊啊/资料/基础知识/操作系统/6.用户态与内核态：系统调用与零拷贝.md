# 用户态与内核态：系统调用与零拷贝

## 为什么分特权级

CPU 的指令分两档：普通指令做运算、访问自己的内存；特权指令操作页表、访问设备、开关中断。相应地 CPU 分两种运行模式：用户程序跑在用户态（x86 的 ring 3），碰不到特权指令与内核数据；内核跑在内核态（ring 0），全部可做。划这条线的目的是让应用再失控也弄不坏系统——一个进程越界写内存，受害的是它自己（段错误）；用户态根本不存在「写坏内核」这个选项。

## 系统调用

应用要用内核的服务——读文件、建 socket、fork——唯一入口是系统调用（system call）：库函数（read、write、fork、epoll_wait 这些 C 库接口都是包装）把系统调用号和参数放进寄存器，执行 syscall 指令；CPU 切到内核态、换到该线程的内核栈，按调用号分发到内核里的实现，执行完返回用户态、恢复现场。一切 I/O 与一切进程线程操作都经这条路，epoll_create、epoll_ctl、epoll_wait 也是三个系统调用（见 [[1.IO 多路复用：从 select 到 epoll]]）。单次开销在亚微秒到微秒级，不算贵，但高频小调用累计可见。

## 中断与异常

进内核不止系统调用一条路。中断是异步的外部事件：网卡收到数据、磁盘完成读取、时钟到点，CPU 暂停当前代码、进内核执行对应处理程序再回来。时钟中断尤其关键——它给内核定期接管 CPU 的机会，调度器靠它才能从一条死循环线程手里拿回 CPU（调度机制见 [[2.进程与线程：内核视角与上下文切换]]）。异常是同步的、由当前指令触发的：缺页、除零、非法指令，处理完通常回到触发的那条指令重试（缺页换入页后重访就能成功，见 [[4.虚拟内存：页表、缺页与页面置换]]）；系统调用属于自愿的陷入，常归为异常一类。

## 模式切换与进程切换的关系

一次系统调用只发生模式切换（用户态进内核态再回来），地址空间没换，还是同一个进程在同一条线程上。进程切换不同：先经中断或系统调用进内核，调度器选中别人，然后换页表、刷 TLB、恢复另一个执行流的现场（见 [[2.进程与线程：内核视角与上下文切换]]）。「系统调用贵」与「进程切换贵」是两笔账：前者是进出内核的固定开销，后者在这之上叠加地址空间切换与缓存变冷的代价。

## 零拷贝

减少模式切换与数据拷贝的招牌案例是服务端发文件。传统 read 加 write 的路径：

```text
磁盘 → DMA → 页缓存（内核） → CPU 拷贝 → 用户缓冲区     ← read()，一次系统调用
用户缓冲区 → CPU 拷贝 → socket 缓冲区 → DMA → 网卡      ← write()，又一次系统调用
```

一次发送 4 次拷贝（2 次 DMA、2 次 CPU）、4 次模式切换（两次系统调用各一进一出），而数据在用户缓冲区只是路过，应用一个字节都没消费。两条优化线：mmap 把页缓存直接映射进地址空间，省掉「页缓存到用户缓冲」那次 CPU 拷贝；sendfile 更进一步，一次系统调用让数据全程不出内核，从页缓存直送 socket 缓冲区，网卡支持分散/聚集 DMA 时连那次 CPU 拷贝都免了，整条路只剩两次 DMA。nginx 对静态文件默认走 sendfile，是高并发文件服务的标配。

> [!example] 实践例子
> Worker 的一条线程在用户态跑协程代码，每轮事件循环调一次 epoll_wait 进出内核取就绪事件（机制见 [[1.IO 多路复用：从 select 到 epoll]]）；LLM 的 token 到达、数据库的返回，都由内核缓冲区经 read 系统调用进入进程。请求处理的大部分时间协程挂在 await 上、线程停在内核的 epoll_wait 里——真正花在模式切换上的开销每轮只有一次，这是单线程事件循环在系统层的成本结构（见 [[7.版本控制与并发]] 的 Worker 进程模型）。sendfile 则是反方向：把「数据只路过用户态」的场景整个搬进内核，nginx 反代静态资源走的正是这条路。

## 边界问答

**1. Q：** 系统调用的开销花在哪？
**A：** 进出内核的固定动作：切栈、保存恢复现场、按调用号分发，外加 TLB 与缓存的扰动。单次不贵，高频小调用累计可见——io_uring 用「批量提交、异步完成」砍的就是这笔（见 [[1.IO 多路复用：从 select 到 epoll]] 边界问答）。

**2. Q：** 零拷贝省掉的到底是哪几次拷贝？
**A：** 传统路径 4 次拷贝 4 次切换。mmap 省掉「页缓存到用户缓冲」的 CPU 拷贝；sendfile 让数据全程不出内核，配合支持分散/聚集的网卡只剩两次 DMA，CPU 拷贝清零。

**3. Q：** 中断和异常都进内核，差别在哪？
**A：** 中断异步，由外部设备随时插入，与当前执行的指令无关；异常同步，由当前指令触发（缺页、除零、系统调用陷入），处理完通常回到触发点继续。
