> [!info] 概念归属
> 本目录是 MCP（Model Context Protocol）框架知识的唯一归属地，分两类板块：第 1 板块「重点知识」从 agent 应用层视角组织（上下文怎么组织、工具怎么调用、出错怎么决策），是面试复习的切入入口；第 2–6 板块按官方规范（2026-07-28 版）自身体系展开协议细节。健康管理项目不进入知识正文，只以两种方式出现：各概念笔记末尾的「实践例子」callout，与本文末尾的板块↔项目章节对照表。

# MCP 总览

建这个目录的原因：MCP 是工具接入方向事实上的行业标准协议，面试讲工具运行时与多智能体架构时绕不开它的口径；而它的规范在 2026-07-28 版做了一次大幅重写（无状态核心、MRTR、头部路由），网上大量资料还停留在 2025-06-18 以前的形态，需要一处按当前官方规范整理、并标注各特性废弃状态的笔记。整理以 modelcontextprotocol.io 的 2026-07-28 规范页为准（2026-09-08 抓取），版本沿革参考各版官方 changelog。

切入入口是第 1 板块「重点知识」：站在 agent 应用使用者的角度讲上下文组织、工具调用与错误决策，不展开协议字段，需要深挖时从各篇链接进入第 2–6 板块。六个板块各一个编号子目录，总览留在本目录根上；笔记文件名保留「板块号.序号」前缀（如 `3.3`）。所有笔记的口径基线是 2026-07-28 版，旧版本行为只在版本沿革与向后兼容的语境下出现。

## 搬运工作流

1. 来源是 MCP 官方规范站（modelcontextprotocol.io/specification/2026-07-28 及各版 changelog），规范正文优先于博客与 SDK 文档。
2. 给 URL 或贴原文，提取后归入对应板块，整理成概念笔记：frontmatter（tags、类型: 概念笔记、状态）→ 概念讲解 →「实践例子」callout → 边界问答。
3. 概念讲解只写协议本身；项目对照只进 callout，一到两句加链接。
4. 涉及版本差异时标明版本号；已废弃特性必须带废弃状态与迁移路径，不写成当前可用能力。
5. 笔记落盘后回本文勾选清单；粒度有变同步改清单。
