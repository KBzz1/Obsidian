# 动态中断：interrupt() 与 Command(resume)

## interrupt()：节点内部抛出的动态断点

interrupt() 是 LangGraph 的动态中断原语：在节点函数内部任意位置调用 interrupt(值)，图执行在该处暂停，值作为中断载荷交给图外部的调用者。「动态」指停点写在节点代码里，位置任意、可按运行时条件决定是否触发；相对的静态断点是 compile 时按节点名声明的停点，见 [[4.2 静态断点与审批、编辑模式]]。

用 interrupt() 有三个前提，缺一不可：

```python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt

checkpointer = InMemorySaver()            # 前提一：checkpointer——中断现场要随检查点持久化，
                                          # 生产环境换成数据库后端的持久实现
graph = builder.compile(checkpointer=checkpointer)

config = {"configurable": {"thread_id": "thread-1"}}  # 前提二：config 里的 thread_id——
                                                      # 运行时靠它知道该恢复哪条线程的状态

def approval_node(state: State):
    approved = interrupt("Do you approve this action?")  # 前提三：载荷必须可 JSON 序列化——
                                                          # 中断值要持久化并在图内外传递
    return {"approved": approved}         # 恢复后 resume 值成为 interrupt() 的返回值，从这里继续
```

中断触发时，checkpointer 保存当时的图状态，图停下无限期等待。中断值本身不写入任何 channel、不占用 state 字段：它交给图外部取回，作为独立的中断现场随检查点持久化——落库时它以 pending writes 形态进入检查点的待处理写入，机制见 [[2.1 LangGraph 检查点与 Channel#中断与恢复]]。需要进 state 的内容，由节点恢复后自己返回写入。

取回中断值有三条路：

```python
result = graph.invoke({"input": "data"}, config)
result["__interrupt__"]     # invoke() 形态：中断值出现在结果的 __interrupt__ 键下

stream = graph.stream_events({"input": "data"}, config=config, version="v3")
stream.interrupted          # stream_events（version="v3"）形态：本次运行是否因人工输入暂停
stream.interrupts           # 中断载荷元组，元素形如 Interrupt(value=...)

# 第三条路读线程状态：Agent Server 的 GET /threads/{thread_id}/state
# 在顶层 interrupts 与 tasks[].interrupts 里返回 Interrupt(id, value)
```

## Command(resume)：从图外部提交答案

恢复不是调用图对象上的某个方法，而是带着答案重新调用图：输入不再是普通 dict，而是 Command(resume=值)，thread_id 必须沿用中断时的那个。官方把 thread_id 称作持久游标：复用它就从同一份检查点恢复，换新值则开启一条空状态的新线程。

```python
from langgraph.types import Command

graph.invoke({"input": "data"}, config)                # 第一次运行：跑到 interrupt() 处暂停
graph.invoke(Command(resume=True), config=config)      # 恢复：resume 值成为节点内
                                                       # interrupt() 调用的返回值
```

resume 值与 interrupt 值是两个方向的数据：interrupt(值) 的实参是从图里发出去的载荷——问题、待审内容；Command(resume=值) 的实参是从图外送回来的答案，它成为那次 interrupt() 调用的返回值，节点代码据此分支。两者类型互不约束，由节点按约定解析。官方同时提醒：Command(resume=...) 是唯一合法的 Command 输入形态，不能把 Command(update=...) 当作图的输入。

多个并行分支同时中断时，一次恢复要给每个中断配对答案，按中断 id 建映射：

```python
resume_map = {i.id: f"answer for {i.value}" for i in stream.interrupts}
graph.stream_events(Command(resume=resume_map), config=config, version="v3")
```

## 节点重入：恢复从节点开头重跑

恢复的语义是整个节点从头重新执行，不是从 interrupt() 那一行续行——节点里 interrupt() 之前的代码会再跑一遍。引擎如何带 resume 值重入停住的节点，检查点层面的机制在 [[2.1 LangGraph 检查点与 Channel#中断与恢复]] 已经讲过，这里记这条语义对节点代码的约束：

1. 中断前的副作用必须幂等，或者挪到 interrupt() 之后执行，或者拆进独立节点。
2. 不要用 try/except 包住 interrupt()——它靠抛一个特殊异常把中断传回图引擎，被捕获后中断就传不回去了；要捕获也只捕获具体的异常类型。
3. 同一节点内多次调用 interrupt() 时，恢复值严格按调用顺序的索引匹配，不能重排、跳过或放进非确定的循环；子图场景下，父图里调用子图的节点与子图内含 interrupt() 的节点都从头重跑。
4. 循环收集人工输入（答案不合法就重问）时，一次节点调用只放一个 interrupt()：把错误提示写进 state 返回，用条件边把节点重新调度回来。不要写 while True + interrupt()——每次恢复都会重放循环体里之前所有轮次的代码，嵌套时呈指数放大。

## NodeInterrupt：被 interrupt() 取代的旧 API

在 interrupt() 出现之前，节点里停图靠抛异常：raise NodeInterrupt(value, id=None)。这个类继承 GraphInterrupt，文档定义就一句——由节点抛出以中断执行，构造参数 value 是随中断保存的载荷，id 是可选标识。官方 API 参考现在直接在它头上挂弃用警告：NodeInterrupt is deprecated. Please use interrupt instead。新代码一律写 interrupt()，NodeInterrupt 只在读旧代码时会遇到。

> [!example] 实践例子
> interrupt() 与 Command(resume) 只提供「停下来、把答案带回来」的原语；停下来之前固化什么、恢复之前校验什么，是框架之上的业务层——健康管理项目在等待前后自建了恢复校验链（任务存在性、过期、任务与草稿版本、调用实例冻结参数、业务前置条件）以及工具调用实例的提议/执行分离与幂等防重放，见 [[6.HIL 与恢复]]、[[5.护栏]]。

## 边界问答

**1. Q：** 恢复时的输入应该传 Command(resume=...) 还是 None？
**A：** 动态中断用 Command(resume=...)，resume 值成为 interrupt() 的返回值；None 输入对应静态断点续行——不给新输入，从检查点继续跑到下一个断点，见 [[4.2 静态断点与审批、编辑模式]]。

**2. Q：** 中断值为什么不放进 state？
**A：** 中断值是发给图外部的问题，state 是图内部流动的数据。官方模式里中断值只通过 __interrupt__ 与 stream.interrupts 交给外部，节点恢复后自己决定把答案写进哪些 channel；审阅前编辑模式正是靠这一点把编辑后的内容写回 state（见 [[4.2 静态断点与审批、编辑模式]]）。

**3. Q：** 并行分支同时中断，恢复一次够吗？
**A：** 够，但要按中断 id 建映射传给 Command(resume=...)，每个中断各配各的答案，运行时按 id 配对，不能只给一个裸值。

**4. Q：** 节点在 interrupt() 之前调了外部 API，恢复时会怎样？
**A：** 会再调一次——恢复是节点从头重跑。所以中断前的副作用必须幂等，或者挪到 interrupt() 之后、或拆进独立节点。

**5. Q：** raise NodeInterrupt 还能用吗？
**A：** 类还在 langgraph.errors 里，但官方 API 参考已标注 deprecated，指明改用 interrupt()。新代码写 interrupt()。
