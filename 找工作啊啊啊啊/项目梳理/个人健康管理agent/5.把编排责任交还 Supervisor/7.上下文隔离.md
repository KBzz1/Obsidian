# 上下文隔离

## 谁持有什么上下文

会话主管保存完整主会话上下文，领域智能体默认采用独立的工作上下文。

调用训练智能体（Workout Agent）时，不执行 `workout_agent.invoke(supervisor.messages)`，而是通过上下文装配（Context Assembly）将会话主管（Supervisor）当前任务转换为领域输入：

```text
会话主管上下文（Supervisor Context）
        ↓
领域上下文装配（Domain Context Assembly）
        ↓
训练系统提示词（Workout System Prompt）
+ 当前领域任务（DomainTask）
+ 相关用户事实
+ 所需记忆 / 检索增强证据（Memory / RAG evidence）
+ 上游产物（Artifact）
        ↓
训练智能体
```

这样训练智能体（Workout Agent）能看到完成任务所需要的信息，却不会长期看到与训练无关的饮食工具链路追踪（Tool Trace）、历史闲聊以及其他智能体的内部过程。

LangChain 当前官方子智能体（Subagents）模式默认同样将主会话记忆保存在主智能体（main agent），并让子智能体（Subagent）每次调用从独立上下文开始；其主要收益就是上下文隔离（context isolation）。

## 用 Subgraph 实现时的映射

如果使用 LangGraph 子图（Subgraph）实现领域智能体（Domain Agent），可以采用父状态（Parent State）与领域状态（Domain State）不同模式（schema）的形式，由包装器（wrapper）显式完成输入输出映射。官方文档也将这种方式作为在多智能体（Multi-Agent）中维护私有消息历史（private message history）的常见模式。

## 单次调用持久化

领域智能体默认采用单次调用持久化（per-invocation persistence）：每次新任务工作上下文从干净状态开始，但单次调用（invocation）内仍可继承父图检查点存储（Checkpointer），从而支持中断（interrupt）和持久执行（durable execution）。只有未来某个领域智能体（Domain Agent）必须自己持续多轮和用户交流时，才需要按线程（per-thread）子图。LangGraph 当前同样将单次调用（per-invocation）作为多数子智能体（Subagent）场景的推荐默认值。

## 隔离不是免费的

一次会话主管→ 领域智能体→ 会话主管（Supervisor）一定比会话主管直接回答增加模型调用。因此系统首先通过减少无意义委派控制成本，而不是为了省一次模型调用让所有智能体共用完整历史。

提示词缓存（Prompt Cache）只能优化重复输入的成本和延迟，不能消除模型仍然需要面对无关上下文的问题。领域智能体（Domain Agent）的系统指令（system instructions）、工具模式（tool schemas）和领域规则应该保持稳定，放在提示词（Prompt）的稳定前缀（prefix）；当前任务（Task）、用户事实和产物（Artifact）放在动态部分。OpenAI 当前提示词缓存（Prompt Caching）指南也建议保持指令（instructions）、工具（tools）和模式（schemas）稳定，并将用户相关动态内容放在稳定前缀（prefix）之后。

完整的上下文装配（Context Assembly）和提示词缓存（Prompt Cache）策略回到第二章设计。第五章只确定三点：

```text
会话主管拥有会话上下文。

领域智能体拥有任务局部工作上下文。

智能体之间交换任务（Task）与产物（Artifact），
而不是完整的执行历史。
```

## 边界问答

**1. Q：** 为什么不直接将会话主管（Supervisor）的完整消息（messages）传给领域智能体？

**A：** 完整消息（messages）里包含与当前领域无关的工具链路追踪（Tool Trace）、历史闲聊和其他智能体的内部过程。通过上下文装配（Context Assembly）转成领域输入，领域智能体（Domain Agent）只拿到完成任务所需的信息，长期隔离无关上下文。

**2. Q：** 为什么默认单次调用持久化（per-invocation persistence）而不是按线程（per-thread）？

**A：** 每次新任务从干净状态开始符合多数子智能体（Subagent）场景，单次调用（invocation）内仍可继承父图检查点存储（Checkpointer）支持中断（interrupt）和持久执行（durable execution）。只有某个领域智能体必须自己持续多轮和用户交流时，才需要按线程（per-thread）子图。

**3. Q：** 上下文隔离增加了模型调用，为什么不干脆让所有智能体共用历史？

**A：** 共用历史只是省掉一次模型调用，代价是每个智能体都要面对无关上下文。成本控制靠减少无意义委派，而不是牺牲隔离换一次调用。

**4. Q：** 提示词缓存（Prompt Cache）能解决无关上下文的问题吗？

**A：** 不能。它只优化重复输入的成本和延迟，模型仍然要面对无关上下文。所以稳定指令放前缀（prefix）、动态任务数据放动态部分，只优化缓存可复用性，隔离问题本身靠上下文装配（Context Assembly）解决。
