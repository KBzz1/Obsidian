# 生产运行时治理边界

生产运行时治理（Production Runtime Governance）位于任务运行时、智能体运行时、工具运行时和后台任务执行机制之外，负责这些运行时并行运转时的资源与运行秩序。前面的章节已经分别定义了任务如何推进和恢复、智能体如何执行、工具如何安全可靠调用，以及多智能体和异步任务如何协作；本章不重新设计这些运行时的内部逻辑，只在它们之上增加统一治理。

各运行时的分工保持原样。第一章定义的任务运行时仍负责任务的创建、推进、中断、检查点（Checkpoint）和恢复（见 [[5.Task Runtime、Checkpoint 和业务状态]]）；第四章定义的工具运行时仍负责一次工具调用的参数校验、权限检查、人工介入（HIL）、幂等、重试和工具结果（见 [[4.统一 Tool Runtime]] 与 [[6.可靠执行]]）；第五章定义的多智能体与异步任务机制仍负责领域任务（DomainTask）的业务协作（见 [[3.多智能体边界与升级标准]]）。第六章只关心这些任务在同一运行环境中竞争有限资源时应该如何被约束。

因此本章的治理对象是逻辑任务，而不是单纯的 HTTP 请求。一个用户请求可能只产生一次模型调用，也可能进入训练智能体（Workout Agent）或饮食智能体（Diet Agent），连续执行多轮模型调用、知识检索和工具调用，还可能因为人工介入暂停后再次恢复。仅限制 HTTP 请求并发无法准确描述这种资源消耗，因此系统以智能体任务（Agent Task）作为生产运行时治理的基本单位，并在任务之上实施预算、排队、优先级和并发限制。

## 边界问答

**1. Q：** 生产运行时治理和第一章的任务运行时是什么关系？

**A：** 两者是不同层级。任务运行时负责单个任务的创建、推进、中断、检查点和恢复，是执行正确性；生产运行时治理位于这些同时运行的运行时之上，约束任务竞争有限资源时的预算、排队、优先级和并发，是运行秩序。第六章不重新设计任务运行时的内部逻辑。

**2. Q：** 为什么治理对象是逻辑任务而不是 HTTP 请求？

**A：** 一个用户请求可能只产生一次模型调用，也可能进入领域智能体连续执行多轮模型调用、知识检索和工具调用，还可能因人工介入暂停后恢复。仅限制 HTTP 请求并发无法描述这种资源消耗，因此以智能体任务作为治理基本单位，在其上实施预算、排队、优先级和并发限制。
