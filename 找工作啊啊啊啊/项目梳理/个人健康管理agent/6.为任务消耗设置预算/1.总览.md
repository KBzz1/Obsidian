# 第六章 总览：为任务消耗设置预算

> [!warning] 实现状态
> 本章描述的是当前定稿的设计与代码级逻辑（数据结构、调用链、状态表），尚未在本仓库完成真实代码落地。逐机制状态见 [[实现真实性地图]]。

## 章节定位

第六章回答一个问题：一个能够长期运行的智能体任务（Agent Task），最多允许消耗多少系统资源。

这个问题由前面几章叠加出的能力引出，不需要假设用户规模：第一章让一个任务可以跨 HTTP 请求暂停和恢复，第五章又允许一个任务跨多个智能体、多轮模型调用、多个工具调用、人工确认和后台执行。任务的生命周期从此远超一次请求，一次请求的到达数量不再代表这个任务实际消耗的资源——一个任务内部可能发生几百次模型调用，而它对外的 HTTP 请求只有几次。Task Runtime（任务运行时）解决的是任务怎样正确地活着、暂停、恢复；本章进一步解决这样一个能够长期存在的任务，最多允许占用多少模型、工具和执行资源。

本章回答四个问题：

- 单个任务最多能消耗多少模型调用、工具调用和执行时间
- 多个任务如何排队、按什么优先级、以多大并发执行
- 系统处理能力饱和时如何限制继续接收任务
- 外部依赖持续失败时如何停止无效调用，并观察运行状态

## 章节边界

第六章只处理多个任务同时运行时对有限资源的约束。以下概念**不在本章展开**，各有归属章节：

| 不在本章展开 | 归属章节 |
| --- | --- |
| 任务的创建、推进、中断、检查点（Checkpoint）与恢复 | 第一章 · Harness 控制平面与任务状态编排 |
| 单次模型调用装配哪些上下文、智能体状态（Agent Status）如何进入上下文 | 第二章 · 上下文工程与能力渐进装载 |
| 长期记忆写入、RAG、证据装配 | 第三章 · 长期记忆、知识 RAG 与证据装配 |
| 一次工具调用的参数校验、权限、人工介入（HIL）、幂等、重试与工具结果 | 第四章 · 工具运行时与纵深安全控制 |
| 多智能体业务协作、领域任务（DomainTask）、异步任务业务语义 | 第五章 · 多智能体协作与异步任务执行 |
| 完整执行链分析、智能体质量评估、Rubric、LLM-as-Judge、回归测试 | 后续测试与评估章节 |

> [!note] 治理对象是逻辑任务，不是 HTTP 请求
> 一个用户请求可能产生多轮模型调用、检索和工具调用，还可能因人工介入暂停后恢复；仅限制 HTTP 请求并发无法描述这种资源消耗，因此以智能体任务（Agent Task）作为治理基本单位。

> [!note] 熔断不会停止整个智能体系统
> 只有真正依赖该外部服务的执行路径受影响，不相关的任务、工具和本地业务能力继续运行。

## 与其他章节的接口

第六章在生产运行时层实施治理，具体机制仍复用前面章节的接口：

- 与第一章的接口是任务状态：任务预算的使用量随任务运行状态一起持久化（见 [[5.Task Runtime、Checkpoint 和业务状态]] 与 [[4.任务预算与任务准入]]）；人工介入等待由第一章保存检查点，第六章负责释放执行槽位。
- 与第二章的接口是预算投影：任务预算生成面向智能体的简化投影，通过智能体状态进入模型上下文（见 [[4.AgentStatus 当前工作状态栏]]），用于指导决策，真正的限制仍由运行时强制执行。
- 与第四章的接口是重试与熔断分层：第四章的重试判断「这一次调用是否值得再次尝试」（见 [[6.可靠执行]]），第六章的熔断判断「这个依赖整体是否还值得继续访问」；工具内部的超时与重试上限仍由工具运行时策略管理。
- 与第五章的接口是任务类型与后台任务：会话主管（Supervisor）可以提交 `task_type` 和 `difficulty`，由 Harness 映射到预算策略（见 [[4.Supervisor 架构与委派]]）；记忆巩固（Memory Consolidation）、后台分析等后台任务在资源允许时运行，属于第五章异步任务机制（见 [[9.HIL 与异步任务]]）。
