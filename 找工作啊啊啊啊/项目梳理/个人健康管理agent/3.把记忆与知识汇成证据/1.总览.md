# 第三章 总览：把记忆与知识汇成证据

> [!warning] 实现状态
> 本章描述的是当前定稿的设计与代码级逻辑（数据结构、调用链、状态表），尚未在本仓库完成真实代码落地。逐机制状态见 [[实现真实性地图]]。

## 章节定位

第一章处理任务如何被创建、推进、中断、恢复和结束，第二章处理调用大模型时模型究竟能看到什么。第三章回答的是：跨任务、跨会话的用户长期信息如何保存、如何按需检索，以及这些信息如何与外部知识、业务事实一起整理成可供下游使用的证据。

当前系统把「完整运行状态」与「用户长期信息」严格分开：LangGraph 状态与检查点只记录某个线程的任务执行位置，服务任务推进与恢复；长期记忆以 `user_id` 为主要作用域，记录面向用户的、跨会话持续存在的信息。二者不再混在同一个抽象里（见 [[3.模块定位与职责边界]] 与 [[4.长期记忆语义模型]]）。

本章回答五个问题：

- 哪些信息值得长期保存，哪些只是当前任务的一次性上下文
- 历史事实、长期认知、当前读取状态为什么分成三个数据层
- 当前任务真正需要哪些长期事实与外部知识，何时触发检索
- 记忆与外部知识用什么形式统一交给下游
- 高级记忆处理失败时如何不损坏低层事实、不阻塞普通请求

## 章节边界

第三章只处理「长期信息与外部知识的读取与装配」。以下概念**不在本章展开**，各有归属章节：

| 不在本章展开 | 归属章节 |
| --- | --- |
| 上下文压缩、上下文装配器、能力渐进披露 | 第二章 · 上下文工程与能力渐进装载 |
| 线程检查点与任务恢复（LangGraph 检查点） | 第一章 · Harness 控制平面与任务状态编排 |
| 工具权限、重试、幂等执行与护栏 | 第四章 · 工具运行时与纵深安全控制 |
| 会话主管与领域智能体的协作协议、任务产物移交 | 第五章 · 多智能体协作与异步任务执行 |
| 高并发、全局队列、限流 | 第六章 · 生产运行时治理 |
| 完整 Trace、统一执行轨迹与测试评估 | 后续测试与评估章节 |

> [!note] 本章不决定哪些证据进入 Prompt
> 第三章把四类数据统一装配成证据包后交给第二章；哪些证据进入本轮模型上下文、采用什么顺序、占用多少令牌，由第二章上下文装配器根据任务、状态、预算和阶段决定。装配接口见 [[3.上下文装配器与 ContextPolicy]]。

> [!note] 记忆检索不是全局默认注入
> 会话主管或领域智能体根据当前领域任务显式判断是否需要长期用户信息或领域知识，再调用对应检索；普通常识问题不触发记忆检索。这种按需边界见 [[3.模块定位与职责边界#与多智能体的权限边界]]，避免长期记忆重新变成每个智能体都加载的全局上下文。
