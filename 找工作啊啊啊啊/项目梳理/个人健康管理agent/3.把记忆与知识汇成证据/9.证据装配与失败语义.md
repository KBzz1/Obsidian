# 证据装配与失败语义

## 证据包：第三章的对外产物

第三章最终不会直接返回数据库对象给智能体。用户画像、用户记忆、业务数据库和领域知识四类来源最终统一转成证据包（EvidenceBundle，以带注释的 Python 数据类表示）：

```python
class EvidenceBundle:
    bundle_id: str                     # 证据包身份，检索记录按它引用本包
    user_id: str                       # 归属用户：第二章读取校验「属于当前用户」的依据
    task_id: str                       # 本次任务标识
    run_id: str                        # 所属 Run：证据包按 Task + Run 生成快照
    retrieval_id: str                  # 由哪次检索产生，指向 RetrievalRecord

    created_at: datetime               # 快照时间：过旧即无效的判断依据
    status: str                        # COMPLETE / PARTIAL / FAILED（必需证据是否齐全）

    profile: list[ProfileEvidence]     # 用户画像证据，来自用户画像
    memories: list[MemoryEvidence]     # 用户记忆证据，来自情节 / 语义记忆
    business_facts: list[BusinessEvidence]  # 业务事实证据，来自业务数据库
    knowledge: list[KnowledgeEvidence]      # 领域知识证据，来自领域知识

    conflicts: list[EvidenceConflict]       # 检出的证据冲突
    missing_sources: list[str]              # 缺失的来源（含必需缺失明细）
```

证据来源保持四类。上游智能体产物（Artifact）不是第五类证据来源：产物移交属于第五章的任务协作协议，第二章另有独立的产物读取路径；某个产物可以帮助生成检索条件，但不复制成长期证据（分工见 [[11.代码级逻辑：从用户事实到 EvidenceBundle#读取链 ③：证据装配]]）。

完整性状态与必需性声明配套：检索请求中声明为必需的来源全部存在为 COMPLETE，必需齐全、可选缺失为 PARTIAL，至少一个必需缺失为 FAILED。第二章对应消费：COMPLETE 与可接受的 PARTIAL 可以加载进装配链，FAILED 不进入正常模型调用。

单条证据至少携带：

```python
class Evidence:
    evidence_id: str                   # 证据身份：这条证据在装配产物中的独立标识
    claim_key: str | None              # 主张键：能映射 state_key 时填充，供去重与冲突识别
    value: object | None               # 主张值：如 evening / plan_88@v2

    source_type: str                   # 来源类型，如 semantic_memory / business_db / knowledge
    source_id: str                     # 来源标识，如 S31 / session_1024
    source_version: str | None         # 来源版本 / 哈希，用于复现当时的资料版本

    claim: str                         # 这条证据陈述的事实，给模型和人阅读
    temporal_status: str | None        # 时间有效性：当前 / 历史 / 未知
    confidence: str | None             # 置信度：low / medium / high

    provenance: list[str]              # 溯源引用，指向支持该主张的情节 / 记录
```

`evidence_id` 与 `source_id` 是两种身份：同一个来源可以支持多条不同 Claim 的证据，因此下游（检索记录、上下文清单）按 `evidence_id` 引用证据，来源标识只负责溯源，不再同时承担证据身份。`claim` 文本与 `claim_key + value` 分工：前者给人与模型阅读，后者供运行时按同一主张键去重、识别冲突。

例如一条典型证据：

```python
{
    "evidence_id": "ev_712",             # 证据身份
    "claim_key": "training.availability.workday_training_time",  # 主张键
    "value": "evening",                  # 主张值
    "source_type": "semantic_memory",   # 来自语义记忆
    "source_id": "S31",                 # 记忆标识
    "source_version": "v1",             # 来源版本
    "claim": "用户当前工作日只能安排晚间训练。",  # 证据陈述
    "temporal_status": "current",       # 当前有效
    "confidence": "high",               # 置信度
    "provenance": [                     # 溯源：支持的情节（S31 的证据链）
        "E22",
    ],
}
```

## 装配器的职责

证据装配的职责是统一来源格式、保留出处、标记当前有效性并识别明显冲突，而不是决定所有证据都进入 Prompt。

第二章上下文装配器根据当前任务、智能体状态、令牌预算和任务阶段决定最终模型可见内容。因此完整调用链是：

```text
会话主管 / 领域智能体
        ↓
判断当前任务需要什么信息
        ↓
检索协调器
        │
        ├── 用户画像
        ├── 用户记忆
        ├── 业务服务
        └── 领域知识
        ↓
证据装配
        ↓
证据包
        ↓
第二章上下文装配器
        ↓
大模型上下文
```

## 失败与恢复语义

记忆形成——后台抽取、语义巩固和普通画像更新——不属于普通用户请求必须同步完成的关键路径，因此高级记忆处理失败时不能阻塞普通智能体请求，也不能破坏已经保存的低层事实。但证据检索是否是当前任务的必要前置，由当前任务在检索请求中的必需性声明决定：可选记忆证据失败，返回 PARTIAL 证据包继续；必需业务事实失败，证据装配失败；必需知识证据失败，明确返回缺失。什么检索失败都让模型接着猜，是不被允许的——这与第二章「声明为必需的证据缺失，本轮上下文装配不允许静默继续」闭环（代码级调用链见 [[11.代码级逻辑：从用户事实到 EvidenceBundle#读取链 ④：证据包快照与两阶段检索记录]]）。

各环节的失败处理：

```text
缓冲工作线程失败
→ 原始事件保持 pending，后续可重试

记忆抽取失败
→ 不生成情节，但原始缓冲事件不删除

情节已写入、时间补全失败
→ 情节仍有效，只是部分时间字段暂时未知 / pending

语义巩固失败
→ 不修改旧语义和用户画像，低层情节已持久化，可重新执行巩固

证据冲突无法稳定解析
→ 巩固器返回 UNCERTAIN，不强迫更新画像

向量检索 / 向量嵌入不可用
→ 退化为结构化过滤 + 词法检索

领域知识检索失败
→ 返回缺少知识证据，不让智能体把无法确认的内容伪装成检索结果
```

因此整个记忆处理链路遵循：

```text
原始长期事实优先可靠保存
        ↓
高级抽象允许异步失败
        ↓
失败不能反向损坏历史
```

## 边界问答

**1. Q：** 为什么第三章不直接返回数据库对象，而要包成证据包？

**A：** 四类数据来源格式不同、语义不同，直接返回给智能体会失去统一口径。证据包统一来源格式、保留出处、标记当前有效性、识别冲突，让第二章在此基础上决定哪些进上下文。

**2. Q：** 证据装配是否决定所有证据进入 Prompt？

**A：** 不决定。它只负责装配与标记，是否进入本轮上下文、顺序与令牌预算由第二章上下文装配器根据任务、状态、预算和阶段决定。

**3. Q：** 为什么高级记忆处理失败不能阻塞普通智能体请求？

**A：** 长期记忆不是用户主请求的同步关键路径。高级抽象（抽取、巩固、装配）允许异步失败，失败只影响后续可重试的抽象层，不能反向丢弃或破坏已经可靠保存的低层原始事实。

**4. Q：** 为什么向量检索不可用时能退化为结构化 + 词法检索？

**A：** 三路信号本身相互独立，结构化过滤和词法检索不依赖向量嵌入。某一路不可用时，其余几路仍能提供基础召回，只是语义召回能力下降，不会让检索整体失败。

**5. Q：** 领域知识检索失败时返回什么？

**A：** 返回缺少知识证据，而不是让智能体把无法确认的内容伪装成检索结果。这样模型不会被引诱补编知识，答案的可靠性边界是清晰的（“这部分没有找到证据”），而不是假装的完整。
