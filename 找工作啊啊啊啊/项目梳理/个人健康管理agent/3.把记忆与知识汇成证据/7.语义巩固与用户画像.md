# 语义巩固与用户画像

## state_key：把演化状态锚定成键

`state_key` 是描述一条会随时间演化的用户状态的稳定键，由每张卡片的 `category`、`subcategory`、`key` 组合生成，把围绕同一条用户状态产生的多个情节归并到同一个维度。例如：

```text
training.preference.training_time
diet.restriction.allergy
fitness.goal.primary
interaction.preference.response_style
```

情节记忆写入完成后，不立即扫描用户全部记忆，也不做向量聚类。新情节写入后，只把对应 `state_key` 标记为 dirty：

```text
new Episode
      ↓
state_key dirty
      ↓
Background Consolidator
```

## 语义巩固

后台巩固器只读取：

```text
当前语义
+
尚未处理的新情节
+
少量必要历史情节
+
必要时的业务证据
```

而不是重新读取用户全部长期历史。

巩固器的输出被限制为四种明确状态：

```text
NO_CHANGE
NEW_SEMANTIC
SUPERSEDE
UNCERTAIN
```

`NO_CHANGE` 表示新情节没有改变现有长期认知。`NEW_SEMANTIC` 表示首次形成一个稳定认知。`SUPERSEDE` 表示当前认知发生变化，需要新增一个语义版本，并把旧版本转为 historical。`UNCERTAIN` 表示证据存在冲突或不足以形成稳定判断，系统不强迫产生新的当前语义。

巩固过程中不采用「最新记忆一定优先」或「向量最相似就视为同一事实」的规则，而是区分不同证据类型。大致证据强度为：

```text
明确的当前用户陈述
        >
确定性的结构化业务事实
        >
一段时间内重复出现的行为模式
        >
模型从零散事件产生的弱推断
```

例如用户最近连续在晚上训练，但同时明确说：

```text
我其实更喜欢早上，只是最近加班只能晚上练。
```

系统不应该简单形成：

```text
preferred_training_time = evening
```

而可以区分：

```text
preferred_training_time = morning
current_practical_training_time = evening
```

这样长期记忆表达的是用户真实偏好和现实约束，而不是只根据最近行为覆盖以前认知。这个区分也解释了为什么旧版「相似即覆盖」会丢失「晚练到底是偏好还是现实约束」这个关键区别，见 [[找工作啊啊啊啊/项目梳理/个人健康管理agent/3.把记忆与知识汇成证据/10.困难以及应对办法]]。

## 用户画像：当前状态的读取视图

用户画像表示当前智能体最经常需要读取的用户状态，是长期记忆的当前读取模型。

它只保存预定义、高价值且需要快速访问的字段，例如：

```text
当前健身目标
伤病和运动限制
过敏
饮食限制
训练时间偏好
训练可用时间
器械条件
交互偏好
```

画像不复制全部语义记忆。

画像字段有两类来源。第一类是用户明确提供的权威事实，例如过敏、明确伤病限制和某些固定约束。这些信息验证后可以直接从情节记忆投影进画像，尤其是安全事实，不需要等待语义巩固。

第二类是派生事实，例如长期训练时间偏好或交互方式偏好。这些字段通过：

```text
情节
    ↓
语义记忆
    ↓
画像投影
```

产生。

## 画像投影：尽量确定性

画像投影尽量由确定性程序控制，例如（以带注释的 Python 表示）：

```python
if semantic.state_key == "training.preference.training_time":
    # 当语义记忆表明训练时间偏好发生变化时，把值投影到画像的对应字段
    profile.training_preference["time"] = semantic.value
```

而不是让大模型每次读取整个画像后自由重写 JSON。这样画像的值能被程序解释、能被回归保持一致，而不是依赖模型每次重新判断。

画像中重要字段保留自己的来源：

```python
{
    "value": "evening",              # 当前值
    "source_type": "semantic_projection",  # 来源类型：semantic_projection / user_stated
    "source_memory_id": "sem_301",   # 来源记忆标识
    "updated_at": "2026-08-20",      # 最近更新时间
}
```

这样后续智能体或开发者可以判断一个画像值是用户明确告诉系统的，还是根据长期行为推导出来的。

## 三种更新语义

最终三个数据层采用不同更新语义：

```text
情节记忆
→ 只追加历史记录

语义记忆
→ 版本化派生认知

用户画像
→ 可变当前状态
```

这三种语义不再混在同一个 `UserMemory` 对象里。这也是第三章最核心的结论：历史、长期认知和当前读取状态是三个不同的数据层，各自有不同的更新方式。

## 边界问答

**1. Q：** 为什么用 `state_key` 而不是对整个记忆做聚类来触发巩固？

**A：** 聚类需要扫描全部历史，成本高且边界模糊。`category + subcategory + key` 组合成稳定的 `state_key`，新情节只把对应键标为 dirty，巩固器只需读取相关小范围。

**2. Q：** 为什么巩固器只接受四种输出，不产生「模糊合并」？

**A：** 明确限定为 NO_CHANGE / NEW_SEMANTIC / SUPERSEDE / UNCERTAIN，避免系统在证据不足时强行造出新的当前认知。UNCERTAIN 允许保留冲突、不更新画像。

**3. Q：** 为什么「最近都在晚上练」不直接得出「偏好晚间」？

**A：** 行为模式单独不能证明偏好。用户有时会明确说明真实偏好与现实约束的差异（“我更想早上，只是最近加班只能晚上练”）。巩固区分证据强度，把偏好与当下实际训练时间拆成两个状态，而不是用最近行为覆盖以前认知。

**4. Q：** 为什么画像投影用程序控制，而不是让大模型重写？

**A：** 自由重写会依赖模型每次重新判断，结果不稳定、难回归验证。确定性程序（按 `state_key` 映射到画像字段）能保持一致性，也便于解释某个值来自哪里。

**5. Q：** 画像为什么只保存一部分字段，而不是全部记忆？

**A：** 画像是当前读取视图，只保留预定义、高价值、需快速访问的字段，不复制全部语义记忆。完整历史与长期认知在情节 / 语义记忆层保留，画像只做当前状态的快速投影。
