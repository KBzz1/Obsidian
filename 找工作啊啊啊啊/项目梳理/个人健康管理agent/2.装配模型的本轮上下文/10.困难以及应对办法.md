# 困难以及应对办法

## 早期结构：直连式消息历史

第一版沿用业界早期的直连式设计：用户自然语言指令、模型回复、工具调用及其返回结果，以线性累积的形态存放在历史消息队列里。模型进行下一轮决策时，依靠回溯这条完整消息轨迹来判别当前所处的任务节点。

简短问答式请求下，这个模式还在稳定范围内。真实工程引入复合草稿生成、多轮外部评估、人工确认环节和检查点唤醒以后，单次任务的消息轨迹开始混杂大量跨生命周期的历史阶段。一次典型的高级干预流程里，历史文本可能先后并存「初始草稿」「校验阻断请求」「修改后的待确认草稿」「用户针对子项的驳回动作」。这些历史节点发生时确实是真实的业务状态；到系统完成中断唤醒、执行当前调用时，它们已经降级为失去系统控制权的过期快照（人工确认见 [[6.HIL 与恢复]]，检查点见 [[5.Task Runtime、Checkpoint 和业务状态]]）。

## 问题暴露：模型被迫推断系统状态

继续向模型提供未经筛选的轨迹，模型面对的是充满干扰的输入：

```text
生成计划
→ 工具返回
→ 生成 draft v1
→ 评估器要求修改
→ 修改为 draft v2
→ 等待确认
→ 用户拒绝动作 2
→ 修改请求
```

核心痛点不在于历史数据进入模型视野，而在于其中充斥着逻辑上依然自洽、工程流转中已明确失效的指令节点。后果是模型被迫接管本应由系统运行时履行的职责：从海量且存在潜在逻辑冲突的文本事件中，重新清洗、推导并计算当前准确的执行游标、草稿版本与可用权限。

## 规划器补救没有触碰问题核心

早期方案试图通过挂载规划器节点补救。规划器输出的静态文本计划能描述宏观路径，但无法确证系统在执行时的实时坐标。一旦执行中途遭遇工具宕机、外部介入阻断或系统级恢复，真实流转状态立刻偏离初始计划。如果依然指望执行节点在未经筛选的文本轨迹里自纠错，系统控制权就仍然依赖脆弱的自然语言语义推演。

## 问题定性

最终定性：系统用来保障执行韧性的持久化底层轨迹，与驱动模型单次决策所需的明确工作视图，缺乏架构层面的解耦分离。

## 重构：装配器与确定性投影

定性明确以后，架构重构主动切断了在提示词层面叠加「请仔细阅读历史并推断当前进度」的补丁策略。在底层状态图与模型推理端之间架设显式上下文装配器（见 [[3.上下文装配器与 ContextPolicy]]）：任务阶段定义、流转版本、安全能力等核心指针，先由运行时统一收口并维护在结构化状态中，再经确定性规则投影生成当前工作状态栏（见 [[4.AgentStatus 当前工作状态栏]]）。每次唤醒模型前，状态栏强制覆写生成，注入上下文尾部安全区。模型不再从残缺草稿和过期工具结果里挖掘当前系统状态，直接拿到具备工程权威性的执行议程与环境边界。

伴随这次底层重构，规划器被剥离全局默认调度的越权职责，退化为特定动态场景下的按需计算模块（见 [[9.Planner 按需规划]]）。即便由规划器生成执行计划，产出也必须回写系统结构化状态槽位，由运行时统一解析并纳入议程视图。

## 旧设计与当前架构对照

```text
旧设计架构

完整消息轨迹累加
      +
规划器计划文本
      ↓
模型基于历史文本自行推断
“当前系统运转到哪一步了？”

      ↓

当前演化架构

持久化完整轨迹（保障中断恢复）
      +
结构化运行时状态（确立唯一事实）
      ↓
确定性状态投影转换
      ↓
当前工作状态栏动态生成
      ↓
上下文统一装配器
      ↓
模型获取权威系统指示
“本轮调用亟需完成的确切目标”
```

## 收益与成本

新架构在运行时层引入了更复杂的上下文策略和状态映射开销，并要求每个投影字段严格对齐生命周期。收益是任务阶段定位从基于 LLM 的概率性推测，转为由宿主程序控制的确定性逻辑运算。

## 技术克制

整个迭代周期内，系统没有引入超出当前阶段需要的重型架构组件。针对上下文膨胀，拒绝了向量化检索引擎、多级 LLM 摘要树、复杂流处理中间件等方案。在当前架构约束下，只要未触碰上下文预算（按部署配置推出，见 [[6.历史轨迹与上下文整理]]），直接挂载原始轨迹文本依然稳定且低延迟；突破预算以后，才拉起低频的确定性截断整理。这个取舍切中了当前阶段的核心痛点，控制了基础设施的运维复杂度，向超长周期任务域演进的工程接口留待后续。

## 边界问答

**1. Q：** 为什么早期直连设计在简短问答下没有暴露问题？
**A：** 简短问答的消息轨迹短，模型回溯历史就能判断任务节点。复合草稿生成、多轮外部评估、人工确认和检查点唤醒进来以后，轨迹才混入跨生命周期的过期阶段，直连式设计的缺陷才暴露。

**2. Q：** 为什么没有用「加强提示词让模型自己推断进度」来修复？
**A：** 问题定性是架构层面缺乏解耦，提示词补丁只能把矛盾压下去，任务阶段定位仍然是概率性推测。重构方向是把阶段定位收口到结构化状态和确定性投影，模型只消费结果。

**3. Q：** 为什么拒绝了向量检索、摘要树这些方案？
**A：** 当前部署未触碰上下文预算时，原始轨迹直接挂载稳定且低延迟，重型组件在这个架构约束下是超前投入。系统只在突破预算时拉起确定性截断整理，运维复杂度可控，超长周期任务需要的演进接口保留在以后。
