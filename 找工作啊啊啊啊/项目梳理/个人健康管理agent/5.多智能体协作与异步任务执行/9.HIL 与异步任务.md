# HIL 与异步任务

## Subagent 不持有会话控制权

子智能体（Subagent）默认不拥有与用户的会话控制权。如果训练智能体（Workout Agent）在任务过程中发现缺少必要输入，不直接向用户发送独立消息，而是返回：

```python
AgentResult(
    status="needs_input",
    input_request={
        "field": "available_training_days",     # 缺少的输入字段
        "question": "每周最多可以安排几天训练？"   # 向用户提出的问题
    }
)
```

会话主管（Supervisor）将多个领域请求统一处理，再由主会话向用户发问：

```text
训练智能体（Workout Agent）
      ↓
需要输入（needs_input）
      ↓
会话主管（Supervisor）
      ↓
用户
```

用户补充信息后，根状态图（Root StateGraph）根据对应子任务（ChildTask）恢复执行。

如果某个领域工作流（Domain Workflow）内部存在高风险确认点，也可以触发中断（interrupt），但最终的会话所有权（conversation ownership）仍在会话主管（Supervisor）。官方子智能体（Subagent）文档同样默认子智能体（Subagent）将结果返回主智能体（main agent），而不是直接持有用户交互。检查点（Checkpoint）、中断（Interrupt）后从哪个节点继续、用户回答如何重新映射到任务（Task），属于第一章控制平面的详细设计（见 [[6.HIL 与恢复]]）。

## 三种执行方式

系统明确区分三种执行方式：

```text
同步执行
同请求并行执行
后台异步执行
```

同步执行用于会话主管（Supervisor）下一步立即依赖子智能体（Subagent）结果的场景。

同请求并行是：

```python
await gather(workout_task, diet_task)
```

两项任务并行，但当前请求仍然等待全部必要结果返回。这只是并发优化，不是后台任务系统。

真正的异步执行意味着当前会话不等待任务完成。官方当前子智能体（Subagents）文档也特别区分了后台异步（background async）与 Python `async/await`：真正的 async 是主智能体启动一个后台任务（job）后继续运行，而不是单纯把函数写成 `async def`。

三种执行方式与 Run 的归属：

```text
同步执行 / 同请求并行
→ 同步 DomainTask 拥有自己的 task_id 与 parent_task_id
→ 作为父任务当前 Run 内的嵌套执行，不创建独立 run_id
→ 通过 Domain Agent Span 区分执行主体

后台异步执行
→ 独立 DomainTask 拥有自己的 task_id / run_id / trace_id
→ 通过 parent_task_id 挂回父任务
```

Run 的身份语义见 [[4.Conversation 与 Task 生命周期#任务与 Run]]。

## 进入后台异步运行时的条件

只有满足以下特征的任务才进入后台异步运行时（Async Runtime）：任务明显耗时较长；当前用户响应不依赖结果立即完成；或者任务需要多个智能体 / 外部系统长期执行。

后台任务建立持久化的任务记录（Task Record）：

```python
class AsyncAgentTask:
    task_id: str                     # 任务身份
    parent_task_id: str              # 父任务身份

    assigned_agent: str              # 被指派执行的 Agent

    status: Literal[                 # 任务状态
        "queued",                    # 已入队
        "running",                   # 执行中
        "waiting_input",             # 等待用户输入
        "succeeded",                 # 成功
        "failed",                    # 失败
        "cancelled"                  # 已取消
    ]

    input_artifact_refs: list[str]   # 输入产物引用
    output_artifact_refs: list[str]  # 输出产物引用

    created_at: datetime             # 创建时间
    started_at: datetime | None      # 开始执行时间，可为空
    finished_at: datetime | None     # 结束时间，可为空

    error_code: str | None           # 失败错误码，可为空
```

会话主管（Supervisor）通过统一接口提交和操作后台任务：

```python
handle = async_runtime.submit(task)      # 提交后台任务，拿到句柄
async_runtime.get_status(handle)         # 查询任务状态
async_runtime.cancel(handle)             # 取消任务
```

## 完成如何接回父任务

任务完成后首先持久化产物（Artifact），再产生完成事件：

```text
异步任务
    ↓
领域智能体
    ↓
产物已持久化
    ↓
任务 = 成功（succeeded）
    ↓
任务完成事件
    ↓
父任务可执行（runnable）
```

父任务恢复依赖确定性的任务（Task）状态，而不是让模型重新读取整段聊天并猜测「之前执行到哪里」。

具体的队列（Queue）、工作线程池（Worker Pool）、优先级（Priority）、背压（Backpressure）等生产调度实现属于第六章。第五章只要求异步运行时（Async Runtime）具备持久的任务身份（durable task identity）、状态（status）、结果引用（result reference）和取消/恢复（cancel/resume）接口，不提前引入 Kafka 或复杂分布式任务基础设施。

## 边界问答

**1. Q：** 子智能体（Subagent）缺输入时为什么不直接问用户？

**A：** 子智能体（Subagent）默认不持有会话控制权。它返回 `needs_input`，由会话主管（Supervisor）统一收集多个领域的请求后再由主会话发问，保持会话所有权（conversation ownership）在会话主管（Supervisor）。

**2. Q：** 同请求并行和真正异步有什么区别？

**A：** 同请求并行是 `await gather` 的并发优化，当前请求仍等全部结果返回；真正异步是主智能体启动后台任务（job）后继续运行，当前会话不等待任务完成。官方特意区分后台异步（background async）和 Python `async/await`。

**3. Q：** 什么任务才进入后台异步运行时（Async Runtime）？

**A：** 任务明显耗时较长、当前用户响应不依赖结果立即完成、或者需要多个智能体 / 外部系统长期执行。同步请求和同请求并行覆盖不了这类场景，才走后台。

**4. Q：** 后台任务完成后，父任务怎么知道可以继续？

**A：** 完成链路是「先持久化产物（Artifact）→ 任务（Task）置为成功（succeeded）→ 发任务完成事件 → 父任务可执行（runnable）」。父任务恢复依赖确定性的任务（Task）状态，不靠模型读聊天猜测进度。
