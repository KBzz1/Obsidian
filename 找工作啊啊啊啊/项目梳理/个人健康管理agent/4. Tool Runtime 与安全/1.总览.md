# 第四章 总览：工具运行时与纵深安全控制

## 章节定位

第四章负责解决智能体已经决定调用某项能力以后，这个动作如何安全、可靠地进入真实业务系统。系统不把大模型生成的工具调用直接视为可执行命令，而是将其视为一次结构化动作提议。所有涉及业务数据读取、业务状态修改、跨智能体协作或外部系统访问的工具调用，都需要经过统一的工具运行时，由运行时完成执行身份绑定、护栏检查、可靠执行和结果标准化。

这一设计延续前面章节已经形成的 Harness 原则：智能体拥有提议权，运行时拥有最终执行权；跨系统边界传递结构化对象，而不是依赖提示词中隐式表达的业务语义。训练智能体（Workout Agent）和饮食智能体（Diet Agent）仍然维护各自独立的工具面，长期记忆仍由记忆运行时（见第三章 [[3.模块定位与职责边界]]）管理，业务数据库仍然是正式业务事实的权威来源。工具运行时不改变这些归属关系，只负责把智能体的动作可靠地映射到真实系统。

本章回答四个问题：

- 智能体能调用哪些能力、对它暴露哪些工具、工具以什么语义暴露
- 工具调用如何从模型的一次输出变成真实系统的动作
- 一个动作进入真实业务系统之前要经过哪些护栏
- 动作执行以后如何做到可靠执行、如何标准化结果、如何处理失败

## 章节边界

第四章只处理「真实动作从提议到执行结果」的边界，不承担其他章节的职责。以下概念**不在本章展开**，各有归属章节：

| 不在本章展开 | 归属章节 |
| --- | --- |
| 图中断、检查点（checkpoint）、任务恢复（resume）、任务生命周期 | 第一章 · Harness 控制平面与任务状态编排 |
| 哪些字段、哪些历史工具结果、以完整还是压缩形式进入下一次提示词 | 第二章 · 上下文工程与能力渐进装载 |
| 长期记忆写入、证据装配、业务事实归业务库 | 第三章 · 长期记忆、知识检索（RAG）与证据装配 |
| 领域任务、类型化产物等跨智能体协作协议 | 第五章 · 多智能体协作与异步任务执行 |
| 跨用户限流、资源池、背压（backpressure）、服务级熔断、全局降级 | 第六章 · 生产运行时治理 |

> [!note] 本章只定义工具运行时与人工介入的接口
> 工具运行时可以产生审批请求，并保存副作用工具的调用实例身份，但任务如何中断、检查和恢复仍由第一章根状态图负责（见 [[5.Task Runtime、Checkpoint 和业务状态#LangGraph 检查点语义]]）。

> [!note] 工具调用不等于授权
> 一个工具调用成为真实业务动作之前，还需要经过执行护栏的权限检查与业务规则校验。「调用来自哪个智能体」只说明谁想调用，不代表调用已经被授权。

## 与其他章节的接口

第四章确定的工具运行时会反向要求相邻模块做少量接口配合，这些配合的机制本身仍在各自章节展开：

- 与第一章的接口主要是人工介入（Human-in-the-Loop）与恢复：工具运行时可以产生审批请求，并保存副作用工具的调用实例身份；图中断、检查点、任务恢复和整体任务生命周期仍由第一章根状态图 / 智能体运行时管理。
- 与第二章的接口是工具结果的上下文可见性：第四章负责生成经过输出护栏的结构化工具结果，但哪些字段、哪些历史工具结果、以完整还是压缩形式进入下一次提示词，由第二章上下文装配器决定（见 [[3.上下文装配器与 ContextPolicy]]）。
- 与第三章的接口是业务证据：感知工具从业务数据库或领域知识获得事实以后，可以携带来源、版本和来源追溯信息进入证据装配（见 [[8.证据检索]]），但工具运行时不直接修改长期记忆；业务数据库仍然是正式业务事实的权威来源，长期记忆的写入仍统一经过记忆运行时。
- 与第五章的接口是智能体工具面与结果隔离：会话主管（Supervisor）、训练智能体（Workout Agent）和饮食智能体（Diet Agent）只能调用各自被授权的工具面，工具结果默认保持任务局部和智能体局部；跨智能体信息继续通过领域任务和类型化产物（见 [[6.通信协议与 Artifact]]）传递。
- 与第六章的边界在可靠性范围：第四章处理单次工具调用实例和当前任务内的超时、重试、幂等以及调用级止损；跨用户限流、资源池、背压、服务级熔断和全局降级策略由第六章生产运行时治理负责。
