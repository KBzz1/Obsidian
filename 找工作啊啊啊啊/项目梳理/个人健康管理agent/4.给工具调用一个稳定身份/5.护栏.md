# 护栏

护栏是系统在工具调用链路上设置的安全检查。系统按照数据流把护栏划分为输入护栏、执行护栏和输出护栏三层，它们解决不同阶段的安全问题，不把所有可靠性机制统一包装成一个护栏。

## 输入护栏

输入护栏位于用户输入或外部不可信内容进入智能体决策链之前，负责判断输入是否可以安全进入后续处理。

```text
用户 / 外部输入
        ↓
输入分类
        ↓
提示词注入 / 越狱检测
        ↓
内容审核
        ↓
规则校验
        ↓
智能体运行时
```

- **输入分类**：判断这一条输入属于什么类型、是否值得信任，引导后续检查的侧重。
- **提示词注入 / 越狱检测**：提示词注入（让模型把指令当作数据执行）与越狱（绕过模型安全限制）这类需要理解语义的攻击，不能完全依靠正则规则。
- **内容审核**：对不适合进入决策链的内容做过滤。
- **规则校验**：例如 SQL 注入、非法路径、危险表达式、参数长度和范围等能够确定性处理的问题，优先使用结构定义、白名单、参数化查询和规则校验。

语义型风险和确定性风险采用不同机制处理。例如查询训练历史时，智能体只能传入结构化字段：

```text
start_date
end_date
exercise_type
limit
```

而不是传入任意：

```text
where_clause
raw_sql
filter_expression
```

系统同时为查询范围、最大返回数量等设置明确边界，从动作空间本身降低攻击面。

## 执行护栏

执行护栏位于工具请求和真实业务系统之间，回答当前动作是否具有真实执行资格——这是「谁想调用」到「允许执行」的关键检查。

首先检查调用者、用户范围和领域权限。训练智能体（Workout Agent）即使能够访问训练数据，也只能操作运行时上下文中当前用户的数据，并且不能跨越领域修改饮食业务状态。

随后由具体领域服务或策略执行业务规则检查：

```text
目标计划是否属于当前用户
目标实体是否仍然有效
当前业务版本是否仍然匹配
当前状态是否允许该动作
```

结构校验（检查请求是否符合已声明的参数结构）只保证「请求结构合法」，业务规则校验（检查当前业务状态是否允许该动作）才保证「当前业务状态允许执行」。

对于当前项目中少量高风险工具（例如替换训练计划、发布计划这类直接修改正式业务数据的写操作），采用工具策略 + 人工介入的方式控制。工具描述符可以直接声明：

```text
approval_policy = NONE
```

或：

```text
approval_policy = EXPLICIT_CONFIRMATION
```

工具运行时根据系统策略决定是否需要人工确认，而不是由智能体自己判断「这个操作看起来危险，要不要问一下用户」。

需要人工确认时：

```text
工具请求
    ↓
创建工具调用实例
    ↓
固化待执行参数
    ↓
产生审批请求
    ↓
根 Harness 中断
    ↓
用户批准 / 拒绝
```

人工介入批准的是一个已经确定的业务动作，而不是一段模糊的聊天文本。审批必须绑定具体工具、目标对象和业务参数，避免用户批准 A 后智能体又重新生成 B 并执行。

由于确认过程可能存在时间间隔，用户批准以后运行时还需要重新检查关键业务前置条件。例如审批时当前计划是版本 12，但确认完成之前已经被其他任务更新到版本 13，此时运行时应返回冲突，而不是继续执行已经过时的写操作。

任务如何中断、检查点（checkpoint）和恢复（resume）仍由第一章根状态图负责（见 [[5.Task Runtime、Checkpoint 和业务状态#LangGraph 检查点语义]]），本章只定义工具运行时和人工介入的接口。

## 输出护栏

工具适配器或外部系统返回的数据不能直接进入智能体上下文，必须经过输出护栏。

```text
输出结构校验
敏感字段过滤
个人隐私信息过滤
密钥 / 凭证过滤
内容审核
工具输出注入防护
返回大小限制
显式截断 / 分页
```

由于模型接口使用用户自己的接口密钥，密钥、访问令牌、数据库凭证等不允许进入大模型可见上下文。接口密钥应只在受信任的模型适配器或运行时内部使用。工具错误、调试信息或第三方响应如果意外包含凭证，也必须在结果进入智能体之前完成过滤。

对于超长查询结果，不允许静默截断。例如业务查询实际返回 620 条记录，而当前工具最大只允许返回 100 条时，结果需要明确表示：

```text
returned_count = 100
total_count = 620
truncated = true
next_cursor = ...
```

智能体必须知道自己看到的是部分结果，而不是误把截断结果当成完整业务事实。

第三方网页、知识检索或外部接口中返回的自然语言内容同样被视为不可信数据。即使它已经进入工具结果，也不会因此获得系统指令级别的权限。

## 边界问答

**1. Q：** 为什么护栏不统一叫一个大类，而要分成输入、执行、输出三层？

**A：** 三层护栏解决不同阶段的安全问题，把可靠性机制统一包装成一个护栏会让边界模糊。输入护栏判断输入能否进入决策链，执行护栏判断动作是否有执行资格，输出护栏判断结果能否进入智能体上下文，各自的作用点不同。

**2. Q：** 结构校验和业务规则校验有什么区别？

**A：** 结构校验保证「请求结构合法」，业务规则校验保证「当前业务状态允许执行」。参数结构正确不代表业务状态允许这个动作，例如目标计划不属于当前用户时结构仍然合法，但业务上不应执行。

**3. Q：** 为什么人工介入批准的是一个具体动作，而不是一段确认文本？

**A：** 审批必须绑定具体工具、目标对象和业务参数，避免用户批准 A 后智能体又重新生成 B 并执行。而且确认期间业务状态可能变化，批准后运行时需重新检查关键前置条件，比如版本已从 12 变为 13 时返回冲突，不继续执行过时写入。

**4. Q：** 为什么超长查询结果不允许静默截断？

**A：** 智能体必须知道自己看到的是部分结果，而不是误把截断结果当成完整业务事实。所以结果要显式返回 `returned_count`、`total_count`、`truncated`、`next_cursor`，让下游知道这段数据不完整。
