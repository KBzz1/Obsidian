# 实现真实性地图

> [!info] 这份地图管什么
> 七章文档里同时存在四类内容：仓库里真实存在的旧版实现、当前代码中的雏形、已经确定但尚未实现的新架构设计、为理解与面试训练构造的演化场景。面试和复习时必须能区分它们：不得把设计说成已实现，也不得把构造的演化场景说成真实线上事故。各机制按章列出，口径全库统一。

## 状态口径

- **已实现（旧版）**：仓库里真实存在的代码，作为演化起点保留。
- **雏形**：当前代码中已有初步形态，但未达到文档描述的完整机制。
- **已确定设计，尚未实现**：架构决策已定稿于文档，代码未落地。
- **代码级逻辑已补齐，尚未实现**：设计进一步细化到数据结构、调用链、状态写入时机与异常路径，可以自然翻译成代码；真实代码仍然没有。补齐内容以第一、二、三、四、五章五篇代码级逻辑笔记为准（2026-09-04 起，代码证据阶段产物）。
- **未来改进**：明确推迟到后续阶段的接口或机制。

该状态的条目格式示例（以工具调用实例为例）：

```text
ToolInvocation（工具调用实例）

状态：
代码级逻辑已补齐，尚未实现

已明确：
- 数据结构（字段与两维状态）
- 创建时机（prepare_invocation，get_or_create）
- 参数冻结（arguments_snapshot 还原动作，request_digest 校验一致）
- 与 HIL 的绑定（中断载荷与卡片携带 invocation_id）
- 恢复逻辑（校验链第⑤～⑧步）
- Retry 语义（同一实例多次尝试，Attempt 级执行记录）
- 幂等边界（idempotency_key + 业务侧 source_invocation_id 唯一约束）

真实代码：
暂无
```

## 使用规则

1. 描述任何机制前先查这张表：不把「已确定设计」说成「系统已经具备」，不把构造的演化场景说成线上事故。
2. 旧版实现（第五章分层、直连式历史、请求层资源控制）是真实代码事实，可以放心作为演化起点引用。
3. 机制落地或状态变化时，先更新本表再更新对应章节笔记。
