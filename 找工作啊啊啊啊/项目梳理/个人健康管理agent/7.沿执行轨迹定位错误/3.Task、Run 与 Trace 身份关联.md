# Task、Run 与 Trace 身份关联

统一观测的第一环是身份：一次任务多次执行产生的运行记录，靠什么关联到同一次执行。为什么 Agent 不能只评最终回答、本章需要回答哪四类问题，见 [[找工作啊啊啊啊/项目梳理/个人健康管理agent/7.沿执行轨迹定位错误/1.总览#章节定位|1.总览#章节定位]]。

## 任务身份与 Run

任务身份分两层：LangGraph 检查点层的 `thread_id` / `task_thread_id` 与任务控制层的 `task_id`，两层的关系以第一章为准（见 [[4.Conversation 与 Task 生命周期#身份模型]]）；本章的观测只消费任务级身份。系统以 `task_id` 表示一个逻辑 Agent Task 的稳定身份。一个 Task 可能因为 HIL、异步等待或故障恢复经历多次连续执行，因此进一步使用 `run_id` 标识某一次实际执行阶段，并为每个 Run 建立独立的 `trace_id`（Run 的身份语义见 [[4.Conversation 与 Task 生命周期#任务与 Run]]）。

```text
task_id
→ 一个逻辑任务的完整生命周期

run_id
→ Task 的一次连续执行阶段

trace_id
→ 该 Run 对应的观测链路
```

例如一个任务第一次运行到 HIL 后暂停，用户完成确认后再次恢复：

```text
task_123

├── run_001
│   └── trace_A
│       → Agent 执行
│       → HIL Requested
│
└── run_002
    └── trace_B
        → Resume
        → Tool Execution
        → Completed
```

这样 Task 可以保持稳定的业务执行身份，而 Trace 不需要跨越长时间等待持续存在。`run_id` 由任务运行时创建并通过 RuntimeContext 向 Agent Runtime、Retrieval Runtime 和 Tool Runtime 传递，使不同模块产生的运行记录能够重新关联到同一次执行阶段。

## Trace 如何串联执行过程

一次 Run 的 Trace 只覆盖具有实际工程边界的执行阶段，而不是为所有内部函数创建 Span。典型 Trace 可以包括 Supervisor、Domain Agent、模型调用、Retrieval、Tool Runtime、DomainTask 和最终响应等阶段。

```text
Trace: run_002

Root Task Runtime
│
├── Conversation Supervisor
│   └── LLM Call
│
├── Workout Agent
│   ├── Context Assembly
│   ├── LLM Call
│   ├── Retrieval
│   └── Tool Invocation
│       └── Tool Runtime
│
└── Final Response
```

Trace 中保存调用开始和结束时间、状态、错误类型以及相关 Record 的引用。例如 Tool Span 可以保存 `invocation_id`，Retrieval Span 保存 `retrieval_id`，模型调用 Span 保存 `context_id`。真正的 Tool 参数、执行效果和 Evidence 内容仍然从对应的结构化 Record 中获取，而不是复制到 Trace 中。

## 多 Agent 的 Run 归属

多 Agent 场景沿用同一套身份：同步委派与同请求并行的同步 DomainTask 拥有自己的 `task_id` 与 `parent_task_id`，但只是父任务当前 Run 内的嵌套执行，不创建独立 `run_id`；后台异步 DomainTask 拥有自己的 `task_id`、`run_id` 与 `trace_id`，通过 `parent_task_id` 挂回父任务（三种执行方式与 Run 的归属见 [[9.HIL 与异步任务#三种执行方式]]）。它们如何出现在轨迹中，见 [[5.Retrieval、Tool 与 DomainTask 接入执行轨迹#DomainTask 如何出现在轨迹中]]。

## 边界问答

**1. Q：** 为什么每个 Run 一条独立 Trace，而不是整个 Task 一条 Trace 贯穿始终？

**A：** Task 会因为 HIL、异步等待或故障恢复经历多次连续执行，如果 Trace 跨越长时间等待持续存在，既没有必要也难以维护边界。Run 保持「一次连续执行阶段」的边界，Task 保持稳定的业务身份，Trace 只覆盖有实际工程边界的执行阶段。

**2. Q：** 为什么 Trace 不把 Tool 参数、执行效果和 Evidence 内容复制进来？

**A：** Trace 只负责表达调用关系和执行过程，保存状态、时间以及 Record 引用（如 `invocation_id`、`retrieval_id`、`context_id`）；真正的参数、执行效果和 Evidence 内容保存在各模块的结构化 Record 中，复制进 Trace 会制造两份需要保持一致的数据。

**3. Q：** 为什么同步 DomainTask 不创建独立 `run_id`，异步 DomainTask 创建？

**A：** 同步委派与同请求并行只是父任务当前 Run 内的嵌套执行，没有独立的执行阶段；后台异步 DomainTask 有自己的执行生命周期，需要独立的 `task_id` / `run_id` / `trace_id`，再通过 `parent_task_id` 挂回父任务。
