# ContextManifest 与模型可见上下文

身份把执行记录关联到同一个 Run 之后（见 [[3.Task、Run 与 Trace 身份关联]]），下一个问题是：模型在每一次决策时，实际看到了什么。

## 清单记录了什么

第二章的 Context Assembler 在每次正式模型调用之前生成 ContextManifest，记录本轮模型实际看到了哪些上下文组成以及哪些能力被暴露。它不默认持久化完整 Prompt，而保存必要的引用、版本和摘要信息：

```python
class ContextManifest:
    context_id: str                # 本轮上下文清单身份

    task_id: str                   # 所属任务
    run_id: str                    # 所属 Run：任务的一次连续执行阶段，见第一章
    agent_id: str                  # 本轮调用者，如 supervisor / workout_agent
    stage: str                     # 当前执行节点 / 阶段

    agent_status_hash: str | None  # 本轮状态栏正文的摘要哈希（状态栏每轮重新生成、没有长期身份，见 [[4.AgentStatus 当前工作状态栏]]）

    memory_refs: list[str]         # 进入本轮的长期记忆引用
    business_fact_refs: list[str]  # 进入本轮的正式业务事实引用，如 plan_88@v2；与任务产物分层，不并入 artifact_refs
    evidence_refs: list[str]       # 进入本轮的证据引用，只存 Evidence.evidence_id
    tool_result_refs: list[str]    # 进入本轮的工具结果引用（如 invocation_id）
    artifact_refs: list[str]       # 进入本轮的产物引用

    visible_tool_refs: list[str]   # 本轮实际暴露给模型的工具（名称 + 版本）
    visible_skill_refs: list[str]  # 本轮实际暴露给模型的技能

    prompt_template_version: str   # 本轮使用的提示模板版本
    context_policy_version: str    # 本轮绑定的上下文策略版本，只存版本引用，不复制策略全文
    context_hash: str              # 本轮上下文的摘要哈希
    estimated_tokens: int          # 本轮上下文预估令牌数
```

`evidence_refs` 只保存 `Evidence.evidence_id` 一种身份，证据包归属由 `EvidenceBundle.bundle_id` 与检索记录维护，清单不混用两种 ID（证据身份语义见 [[9.证据装配与失败语义#证据包：第三章的对外产物]]）。完整 Prompt 不作为默认长期观测数据，只有在特定调试或 Eval Case 需要时，才在符合隐私要求的情况下生成脱敏 Snapshot。

## 用清单区分四种失败

这一结构的主要目的不是记录字段本身，而是让评估能够区分四种不同的失败：

- 信息根本没有进入系统——正确资料没有被 Retriever 召回，由检索记录判断（见 [[5.Retrieval、Tool 与 DomainTask 接入执行轨迹]]）；
- Evidence 已经形成但没有进入本轮 Context——查 `evidence_refs`；
- Tool 已经注册但本轮没有暴露给模型——查 `visible_tool_refs`；
- Agent 已经看到正确信息仍然做错——前三种都排除后，归因到 Agent Decision 而不是 Context Assembly。

因此评估系统能够分别定位 Context Assembly 和 Agent Decision 的问题，而不是把所有错误归因到模型本身。例如 Agent 没有选择一个正确 Tool 时，系统可以进一步判断该 Tool 当时是否已经进入模型的可见 Tool Surface；Agent 忽略用户伤病限制时，可以检查相关 Evidence 是否进入了 ContextManifest。这一层的评估指标见 [[8.Agent 分层评估#上下文与 Evidence]]。

## 边界问答

**1. Q：** 为什么不默认持久化完整 Prompt？

**A：** ContextManifest 保存引用、版本和摘要信息，就足以回答「模型当时看到了什么」。完整 Prompt 只在特定调试或 Eval Case 需要时，才在符合隐私要求的情况下生成脱敏 Snapshot。

**2. Q：** 为什么 `evidence_refs` 只保存 `Evidence.evidence_id` 一种身份？

**A：** 证据包的归属由 `EvidenceBundle.bundle_id` 与检索记录维护，清单同时使用两种 ID 会让同一份证据出现两个身份来源，评估时无法判断该沿哪一层追溯。

**3. Q：** 清单如何区分「资料没进系统」和「资料没进上下文」？

**A：** 前者查检索记录，判断正确资料是否被 Retriever 召回；后者查 `evidence_refs`，判断已经形成的 Evidence 是否进入本轮 Context；Tool 是否可见查 `visible_tool_refs`。三者都排除后 Agent 仍然做错，才归因到 Agent Decision 而不是 Context Assembly。
