# 证据装配与失败语义

## 证据包：第三章的对外产物

第三章最终不会直接返回数据库对象给智能体。用户画像、用户记忆、业务数据库、领域知识和上游智能体产物最终统一转成证据包（EvidenceBundle，以带注释的 Python 数据类表示）：

```python
class EvidenceBundle:
    task_id: str                       # 本次任务标识

    profile: list[ProfileEvidence]     # 用户画像证据，来自用户画像
    memories: list[MemoryEvidence]     # 用户记忆证据，来自情节 / 语义记忆
    business_facts: list[BusinessEvidence]  # 业务事实证据，来自业务数据库
    knowledge: list[KnowledgeEvidence]      # 领域知识证据，来自领域知识
    artifacts: list[ArtifactEvidence]       # 上游任务产物，来自智能体产物

    conflicts: list[EvidenceConflict]       # 检出的证据冲突
```

单条证据至少携带：

```python
class Evidence:
    source_type: str                   # 来源类型，如 semantic_memory / business_db / knowledge
    source_id: str                     # 来源标识，如 sem_301 / session_1024

    claim: str                         # 这条证据陈述的事实，如「用户当前主要在晚间训练」

    temporal_status: str | None        # 时间有效性：当前 / 历史 / 未知
    confidence: str | None             # 置信度：low / medium / high

    provenance: list[str]              # 溯源引用，指向支持该主张的情节 / 记录
```

例如一条典型证据：

```python
{
    "source_type": "semantic_memory",   # 来自语义记忆
    "source_id": "sem_301",             # 记忆标识
    "claim": "用户当前主要在晚间训练。",  # 证据陈述
    "temporal_status": "current",       # 当前有效
    "confidence": "high",               # 置信度
    "provenance": [                     # 溯源：支持的情节
        "episode_18",
        "episode_21",
    ],
}
```

## 装配器的职责

证据装配的职责是统一来源格式、保留出处、标记当前有效性并识别明显冲突，而不是决定所有证据都进入 Prompt。

第二章上下文装配器根据当前任务、智能体状态、令牌预算和任务阶段决定最终模型可见内容。因此完整调用链是：

```text
会话主管 / 领域智能体
        ↓
判断当前任务需要什么信息
        ↓
检索协调器
        │
        ├── 用户画像
        ├── 用户记忆
        ├── 业务服务
        ├── 领域知识
        └── 上游产物
        ↓
证据装配
        ↓
证据包
        ↓
第二章上下文装配器
        ↓
大模型上下文
```

## 失败与恢复语义

长期记忆不是用户主请求的同步关键路径，因此高级记忆处理失败时不能阻塞普通智能体请求，也不能破坏已经保存的低层事实。

各环节的失败处理：

```text
缓冲工作线程失败
→ 原始事件保持 pending，后续可重试

记忆抽取失败
→ 不生成情节，但原始缓冲事件不删除

情节已写入、时间补全失败
→ 情节仍有效，只是部分时间字段暂时未知 / pending

语义巩固失败
→ 不修改旧语义和用户画像，低层情节已持久化，可重新执行巩固

证据冲突无法稳定解析
→ 巩固器返回 UNCERTAIN，不强迫更新画像

向量检索 / 向量嵌入不可用
→ 退化为结构化过滤 + 词法检索

领域知识检索失败
→ 返回缺少知识证据，不让智能体把无法确认的内容伪装成检索结果
```

因此整个记忆处理链路遵循：

```text
原始长期事实优先可靠保存
        ↓
高级抽象允许异步失败
        ↓
失败不能反向损坏历史
```

## 边界问答

**1. Q：** 为什么第三章不直接返回数据库对象，而要包成证据包？

**A：** 四类数据来源格式不同、语义不同，直接返回给智能体会失去统一口径。证据包统一来源格式、保留出处、标记当前有效性、识别冲突，让第二章在此基础上决定哪些进上下文。

**2. Q：** 证据装配是否决定所有证据进入 Prompt？

**A：** 不决定。它只负责装配与标记，是否进入本轮上下文、顺序与令牌预算由第二章上下文装配器根据任务、状态、预算和阶段决定。

**3. Q：** 为什么高级记忆处理失败不能阻塞普通智能体请求？

**A：** 长期记忆不是用户主请求的同步关键路径。高级抽象（抽取、巩固、装配）允许异步失败，失败只影响后续可重试的抽象层，不能反向丢弃或破坏已经可靠保存的低层原始事实。

**4. Q：** 为什么向量检索不可用时能退化为结构化 + 词法检索？

**A：** 三路信号本身相互独立，结构化过滤和词法检索不依赖向量嵌入。某一路不可用时，其余几路仍能提供基础召回，只是语义召回能力下降，不会让检索整体失败。

**5. Q：** 领域知识检索失败时返回什么？

**A：** 返回缺少知识证据，而不是让智能体把无法确认的内容伪装成检索结果。这样模型不会被引诱补编知识，答案的可靠性边界是清晰（“这部分没有找到证据”）而不是假装的完整。
