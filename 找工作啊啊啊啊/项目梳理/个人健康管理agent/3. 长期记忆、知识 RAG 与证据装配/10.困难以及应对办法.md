# 困难以及应对办法

## 早期结构：原子事实 + 相似度覆盖

早期版本的长期记忆采用一套比较直接的原子事实模型。会话结束后由大模型从近期对话中抽取值得长期保存的事实，再为文本生成向量嵌入并写入 `UserMemory`。为了避免向量库不断积累语义重复的数据，新事实写入前会先搜索同类旧记忆；当语义相似度达到较高阈值时，系统会把它视为已有事实的更新，直接修改旧记录。另一部分逻辑又采用 `superseded_by` 保存新记忆，并把旧记忆标记为已经被新事实替代。读取时主要返回没有被替代的记忆。

这种方案在第一版里很自然。记忆当时主要被理解成一组「关于用户目前知道的事实」，因此系统希望数据库尽可能保持干净：

```text
会话
    ↓
原子事实抽取
    ↓
搜索相似记忆
    ↓
┌────────────────────────┐
│ 相似度高 → UPDATE       │
│ 不相似   → ADD          │
│ 新事实出现 → supersede  │
└────────────────────────┘
    ↓
当前用户记忆
```

对于「用户身高 175cm」或者「用户不吃牛肉」这类看起来接近静态属性的信息，这套方式通常可以工作。真正的问题出现在用户状态开始随着时间发生变化以后。

## 问题暴露：状态随时间变化

典型场景是训练时间偏好。用户早期可能明确表示「我一般喜欢早上训练」，几个月后因为换工作又说「现在上班时间变了，我基本只能晚上训练」。

从向量相似度的角度，两条记忆都高度围绕「用户 + 训练时间 + 偏好」，因此非常容易被认为是同一个事实。如果按照旧逻辑直接更新：

```text
preferred_training_time = morning
              ↓
UPDATE
              ↓
preferred_training_time = evening
```

数据库确实得到了一个更符合当前状态的值，但「用户过去喜欢晨练」这个事实已经消失。系统此后只能知道用户现在晚上训练，却无法再解释这个变化是何时发生、为什么发生。

使用 `superseded_by` 能保留旧记录，但如果检索默认把被替代的记忆过滤掉，问题只是从「历史被删除」变成了「历史还在数据库里，但智能体正常情况下看不到」。当任务只需要回答「用户现在喜欢什么时候训练」时问题并不明显；一旦用户提出「为什么你现在总把我的训练安排在晚上？」，或者智能体需要判断「晚练到底是用户真正偏好，还是工作变化造成的临时现实约束？」，旧模型就没有足够清晰的数据语义支持这种判断。

## 调阈值与加替代标记都解决不了

继续调整相似度阈值也无法解决这个问题。把阈值从 `0.92` 调高只能减少误合并，却不能回答「什么时候应该更新」这个根本问题。因为「我以前喜欢晨练」和「我现在改成晚练」语义相似度非常高，但两条信息并不是重复事实——它们描述的是同一个用户状态在不同时间的两个有效阶段。

同样，继续增加更多 `superseded_by` 判断也没有真正解决问题。旧设计仍然要求写入阶段回答一个很困难的问题：**新记忆到底是在纠正旧事实，还是描述一个新的历史状态？**

而记忆抽取所看到的通常只是当前一小段会话。让大模型在这个阶段同时理解完整历史、时间关系、用户状态变化，再决定新增、更新或删除，会让一个本来只应该负责「记录新信息」的组件承担过多职责。

## 问题定位：三种语义混在一个抽象里

最终定位到的问题并不是向量搜索效果不好，而是旧系统把三种不同含义的数据放在了同一个 `UserMemory` 抽象中：

```text
发生过什么
+
我们目前根据历史形成了什么认知
+
智能体现在应该快速读取什么状态
```

于是同一次「用户状态变化」同时触发了三种互相冲突的需求：

```text
历史层：
旧事实必须保留

认知层：
当前判断应该变化

读取层：
智能体最好直接得到最新值
```

单个可变记忆记录不可能同时很好地满足这三个要求。因此新版没有继续优化「更新 / 删除 / 替代」的判断 Prompt，而是重新定义了长期记忆的状态边界（这套语义模型见 [[4.长期记忆语义模型]]）。

## 改造第一步：只追加的历史层

把情节记忆变成只追加的历史层。新的用户状态只产生新的情节，不再因为和旧情节高度相似就覆盖过去：

```text
E1
2026-03
用户表示更喜欢晨间训练

E2
2026-07
工作安排变化后改为晚间训练
```

两条情节都长期存在，并分别保存事件时间、主体、背景和原始来源（卡片结构见 [[5.记忆卡片与持久化模型]]）。向量相似度只用于以后寻找相关证据，不再拥有修改历史的权力。

## 改造第二步：版本化的语义记忆

在情节之上增加语义记忆。语义记忆不表示某一次用户陈述，而表示系统结合相关历史证据以后形成的长期认知。状态发生变化时，同样不是修改旧语义内容，而是新增版本：

```text
S1
preferred_training_time = morning
status = historical

        ↓ superseded by

S2
preferred_training_time = evening
status = current
```

`S1` 曾经是正确认知，因此仍然保留；`S2` 表达系统目前应该采用的新认知。语义记忆同时通过 `derived_from` 指向支持它的情节，避免长期抽象和原始证据断开。这个版本化过程由 [[7.语义巩固与用户画像#语义巩固]] 完成。

## 改造第三步：可变的用户画像

把用户画像明确成当前状态读取层。画像本身允许正常更新，因为它的职责就是让会话主管或领域智能体快速得到当前高价值状态：

```text
profile.training_preference.time
morning
    ↓
evening
```

因此新版形成了三种不同的数据更新语义：

```text
情节记忆
→ 只追加
→ 保存历史

语义记忆
→ 版本化
→ 保存长期认知及其变化

用户画像
→ 可变
→ 保存当前读取状态
```

三种更新语义的详细说明见 [[7.语义巩固与用户画像#三种更新语义]]。

## 职责收窄与相似度的位置

在这个结构下，同样一个用户状态变化不再要求记忆写入器做一次模糊的「应该新增还是更新」判断：

```text
用户：
“换工作以后我现在基本晚上训练。”

        ↓

情节记忆
新增一条时间化历史事件

        ↓

语义巩固
判断当前训练时间是否发生变化

        ↓

如果证据足够：
新增新的语义版本

        ↓

画像投影
更新当前训练偏好
```

记忆抽取的职责因此被明显收窄：它只判断当前会话中有没有值得跨会话保存的新事件，并把事件忠实地写入历史层。关于这些事件是否已经构成稳定长期偏好、是否与以前认知冲突、哪个状态当前有效，则交给后续围绕同一 `state_key` 执行的语义巩固（见 [[7.语义巩固与用户画像#state_key：把演化状态锚定成键]]）。

这项改造也改变了向量相似度在系统中的位置。旧版中，相似度同时承担搜索和记忆改写决策：`相似 → 可能更新`。新版中，向量嵌入只负责帮助系统寻找可能相关的历史证据：`相似 → 可能相关 → 交给时间 / 语义判断`（见 [[8.证据检索#相似不再等于同一事实]]）。「相似」不再被解释成「同一个事实」。

## 代价与换得的性质

改造后的代价是长期记忆不再像早期版本一样只有少量最新记录。情节数量会持续增长，语义记忆也会保留历史版本，因此系统需要额外维护 `state_key`、`derived_from`、有效时间和后台巩固。画像也需要明确的投影规则，而不能依赖一张记忆表直接返回结果。

当前项目接受这些额外复杂度，是因为它们直接换来了三个旧设计无法同时提供的性质：

```text
历史可以追溯
当前状态可以快速读取
高层认知可以解释自己的证据来源
```

同时系统没有进一步引入事件溯源、时序知识图谱或复杂记忆图谱。当前用户长期状态主要集中在有限的健身、饮食和交互偏好主题，使用只追加情节、版本化语义和可变画像已经能够解决真实的状态演化问题。只有未来记忆的实体关系和跨事实推理复杂度明显增加时，才有必要继续升级数据模型。

## 边界问答

**1. Q：** 旧版用 `superseded_by` 为什么还不够？

**A：** 它只让旧记录留在库里，但如果检索默认过滤被替代的记忆，历史又变成「智能体正常情况下看不到」。当任务需要解释变化过程、判断「晚练是偏好还是现实约束」时，旧模型缺少足够清晰的语义来支撑判断。

**2. Q：** 为什么调相似度阈值不能解决问题？

**A：** 阈值只影响「是否误合并」，不能回答「什么时候应该更新」。「我以前喜欢晨练」和「我现在改成晚练」语义相似度很高，但描述的是同一个状态在不同时间的两个有效阶段，不是重复事实。这是数据语义问题，不是相似度阈值问题。

**3. Q：** 为什么不让记忆抽取同时判断新增 / 更新 / 删除？

**A：** 抽取阶段通常只看到当前一小段会话，却要求它同时理解完整历史、时间关系和用户状态变化，职责过重。改造后抽取只判断「有没有值得长期保存的新事件」，「是否形成稳定认知、是否与旧认知冲突、当前哪个有效」交给后续巩固。

**4. Q：** 三个数据层不是同一份数据的三个副本吗？

**A：** 不是。情节是只追加的历史层，语义记忆是在历史层之上形成的版本化认知，画像是可变的当前读取视图。三者更新语义、读取用途不同，不能互相替代。

**5. Q：** 为什么这次改变的不是向量库，而是对记忆的理解？

**A：** 旧设计把记忆当成一组需要持续维护为「最新」的可变事实；新版把「历史发生过什么」「当前能够形成什么认知」「智能体此刻需要快速读取什么状态」拆成三个数据层。状态变化不再通过修改过去表达，而是通过新增历史、形成新语义版本、更新当前画像表达。
