# 第二章 总览：上下文工程与能力渐进装载

## 章节定位

第一章处理任务如何被创建、推进、中断、恢复和结束。第二章回答一个更具体的问题：调用大型语言模型（LLM）时，模型究竟能看到什么。

当前设计不再把完整执行轨迹、运行状态和工具调用结果直接当作模型上下文，而是在智能体运行时（Agent Runtime）与模型调用之间引入统一的上下文装配器（Context Assembler）。第一章定义的状态图运行状态、检查点和完整业务草稿仍然作为系统的单一事实来源（Source of Truth）保存，本章机制只负责从这些全局事实中提取、派生和组装当前模型决策所需的子集。

系统在架构层面严格分离「完整运行状态」与「模型工作上下文」。完整运行状态服务系统级的任务推进、中断恢复、故障排查和业务持久化，某段历史记录即便暂时对模型不可见，也不会被系统丢弃；模型工作上下文是单次 LLM 调用的临时视图，受当前执行节点、任务所处阶段和业务领域的共同约束。模型不需要感知底层全局快照，只需要拿到足以支撑本轮决策的最小有效信息（状态与检查点本身见 [[5.Task Runtime、Checkpoint 和业务状态]]）。

本章回答五个问题：

- 单次 LLM 调用看到的内容由谁决定、如何生成
- 当前任务进度用什么形式告知模型
- 上下文逼近预算上限时如何整理
- 不同节点为什么看到的工具和指令不一样
- 规划器什么时候才需要出现

## 章节边界

第二章只处理「当前执行模型能获取何种数据视图」。以下概念不在本章展开，各有归属章节：

| 不在本章展开 | 归属章节 |
| --- | --- |
| 跨会话用户偏好萃取、全局事实记录、RAG（检索增强生成）与知识召回 | 第三章 · 长期记忆、知识 RAG 与证据装配 |
| 多智能体协作协议、任务产物移交、跨域唤醒 | 第五章 · 多智能体协作与异步任务执行 |
| 状态图运行状态与检查点的持久化本身 | 第一章 · Harness 控制平面与任务状态编排 |

本章与第三章的接口是：装配器接收第三章已输出的可信结果，并裁决它们在当前模型上下文中的驻留位置；召回机制本身不在这里展开。

> [!note] Supervisor Context 与 Domain Context
> 第五章引入多智能体后，装配器需要区分 Supervisor Context（完整会话）与 Domain Context（task-local 工作上下文）。这一隔离原则见第五章 [[7.上下文隔离]]，具体的令牌预算、压缩和渐进披露仍在本章展开。
