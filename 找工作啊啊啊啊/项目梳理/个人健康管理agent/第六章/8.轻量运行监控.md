# 轻量运行监控

本章只保留支撑生产运行治理所必需的运行监控，用于确认前面引入的预算、队列、并发限制和熔断机制是否真正发挥作用，不在这里展开完整的 Trace 分析和 Agent 质量评估。

## 观测哪些指标

Task 层主要观察正在运行的 Task 数量、Task Failure 和 Budget Exhausted；队列层观察交互任务与后台任务的 Queue Length 和 Queue Wait Time；外部依赖层观察调用延迟、Timeout、429 和 Error Rate；熔断层记录当前依赖状态、熔断触发次数以及恢复情况。Tool Runtime 已有的失败和 Retry 信息也可以汇总为生产运行指标，用于判断某个工具或依赖是否开始出现系统性异常。

## 监控回答的问题

这些指标的目的不是评价 Agent 回答得是否正确，而是回答生产运行中的几个基本问题：当前系统是否已经过载，任务是否开始大量排队，某类 Task 是否经常耗尽预算，某个外部依赖是否持续异常，以及熔断机制是否频繁被触发。更完整的执行链分析、RAG 和 Tool Calling 质量评估、Rubric、LLM-as-Judge 以及回归测试统一放到后续测试与评估章节中处理。

## 边界问答

**1. Q：** 为什么本章不展开完整的 Trace 分析和 Agent 质量评估？

**A：** 第六章的监控只需要回答「治理机制是否生效」：是否过载、是否大量排队、是否经常耗尽预算、依赖是否持续异常、熔断是否频繁触发。执行链分析、RAG / Tool Calling 质量、Rubric、LLM-as-Judge 和回归测试归后续测试与评估章节。
